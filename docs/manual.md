# tailchat — полное руководство

Консольный P2P 1:1 чат поверх [Tailscale](https://tailscale.com) tailnet.
Ноль конфигурации: оба пира запускают одну команду с адресом друг друга.

## Требования
- Node.js >= 20 на обеих машинах
- устройства доступны друг другу через Tailscale: один tailnet или shared node

## Установка
```bash
npm install
npm link   # опционально, чтобы вызывать `tailchat` глобально
```

## Android (APK)

Нативный клиент для телефона живёт в [`android/`](../android/README.md) — то же
соединение и тот же протокол, но экран вместо терминала. Собирается в APK,
ставится сайдлоадом, разговаривает с обычным `tailchat` на компьютере.

## Запуск
На машине A (её tailnet-имя/IP видно второй как `A`):
```bash
tailchat B --name Alice
```
На машине B:
```bash
tailchat A --name Bob
```
`B`/`A` — MagicDNS-имя или tailnet-IP пира. Порт по умолчанию `4747`
(общий для listen и connect); переопределяется `--port`.

### Облачный режим (необязательно)

Обычный `tailchat B` остаётся прямым P2P-соединением внутри tailnet и вообще не
обращается к облачному серверу. Для аккаунта, списка пользователей и доставки
сообщений выключенному собеседнику запустите:

```bash
tailchat --cloud
```

Клиент проверит сохранённый токен, при необходимости предложит вход или
регистрацию, затем покажет список аккаунтов. Логин собеседника можно передать
сразу: `tailchat roman --cloud`. Свой сервер задаётся базовым URL без `/cloud`:
`tailchat --cloud --cloud-server https://chat.example`. Выйти из аккаунта и
удалить локальный токен: `tailchat --cloud-logout`.

Тот же аккаунт работает в браузере по `https://<домен>/cloud/`. Развёртывание
необязательной службы описано в [`docs/cloud-deploy.md`](cloud-deploy.md).

### Запуск без аргументов

`tailchat` без пира больше не тупик: клиент предлагает тех, с кем ты уже
говорил. Один запомненный пир запускается сразу, без вопросов; если их
несколько — появляется меню, такое же, как список команд в самом приложении:
`↑`/`↓` — выбор, цифра `1`-`9` — сразу взять строку, `Enter` — подтвердить,
`Esc` — отмена. Вернуть меню принудительно: `tailchat --menu` (набранный пир
игнорируется).
```
┌────────────────────────────────────────────────┐
│ ─ с кем говорим? ───────────────────────────── │
│ ❯ ella@example.com    ? отсюда не видно — ella │
│ ↑/↓ выбор · 1-9 номер · Enter подтвердить · Esc отмена│
└────────────────────────────────────────────────┘
```

Кружок намеренно скромен. Локальный демон знает, включено ли **устройство** в
tailnet, но не знает, запущен ли там tailchat — узнать это можно только
постучавшись, а веерного обзвона проект не делает. Поэтому `●` читается как
«устройство в сети», а не «человек в чате». Логин, которого в твоём tailnet
нет вообще (расшаренный узел, чужая сеть), показывается как `?` — выдавать это
за «офлайн» было бы догадкой под видом факта.

Сортировка: сперва доступные, потом неизвестные, потом офлайн; внутри группы —
по алфавиту, чтобы нумерация не плясала между запусками.

Список берётся из того же ростера, что и подключение по имени. Пока ростер
пуст, клиент это и говорит:

```
no peer given, and nobody is remembered yet
name one once — tailchat <peer> — and it will be offered next time
```

В пайпе или скрипте меню нет — печатается пронумерованный список, как раньше,
и висеть на вопросе, который никто не прочитает, клиент не станет.

Тот же выбор есть и внутри приложения: `/peer` открывает то же меню и
переключает разговор, а `/peer <имя>` переключает сразу.

### Первый запуск

Один раз, до первого разговора, клиент спрашивает три вещи, которые иначе
взять неоткуда: язык интерфейса, **имя, под которым вас видит собеседник**, и
вести ли журнал переписки. Ответы сохраняются в `~/.tailchat/config.json`:

```json
{ "lang": "ru", "log": true, "name": "alex" }
```

Журнал по умолчанию **ведётся** — свой файл на разговор в `~/.tailchat`
(`peer-<пир>-<хэш>.log`, права `0600`), конец восстанавливается при запуске,
`/history` его показывает. Отключить: `--no-log` при запуске или «Нет» в
мастере. Явный `--log <файл>` всегда побеждает.

Язык можно задать и без мастера: `tailchat lit --lang ru` на один запуск или
`export TAILCHAT_LANG=ru` в профиле оболочки. Порядок: флаг → переменная
окружения → сохранённый выбор → локаль терминала.

Имя фиксированное и спрашивается ровно один раз. До этого его не было в
настройках вообще: клиент подставлял `hostname`, а он у каждой машины свой —
на Android несколько устройств вообще сообщают о себе как `localhost`. Из-за
этого один и тот же человек появлялся у собеседника под разными именами,
смотря с чего отвечал. Теперь имя одно и то же на всех машинах, где вы
запускаете клиент под своим `~/.tailchat`.

Поменять потом: `/name Роман` в чате — имя сохраняется, и клиент перезапускается,
потому что имя уходит собеседнику в кадре `hello` при открытии канала. Без
аргумента `/name` показывает текущее. `--name <имя>` перебивает сохранённое на
один запуск; порядок тот же, что у языка: флаг → сохранённый выбор → `hostname`.

Ограничения простые и не на вкус: до 32 символов (иначе имя выдавит имя
собеседника из шапки) и без двоеточия — журнал пишется строкой
`[ЧЧ:ММ] имя: текст`, и двоеточие внутри имени делает такую строку
неразбираемой. Пробелы внутри имени разрешены: `Роман К` — это имя.

### Пир как пользователь Tailscale

Вместо адреса устройства можно указать самого человека — логин, отображаемое имя
или имя любого его узла:

```bash
tailchat roman@example.com --name alex
tailchat roman --name alex          # достаточно части логина или имени
```

Что это меняет:

- **Входящие принимаются с любого его устройства.** Личность подтверждает
  `tailscale whois` — отвечает локальный tailscaled по карте tailnet, пир этот
  ответ подделать не может. Новый ноутбук или телефон заработает без правки
  настроек на другой стороне.
- **Исходящий канал один, маршрутов несколько.** Сначала клиент звонит по
  адресу, который сработал в прошлый раз (он помнится между запусками в
  `~/.tailchat/peer-*.json`, права `0600`), затем последовательно перебирает
  IPv4, IPv6 и MagicDNS-имена всех известных устройств. Попытки не идут
  параллельно: следующий маршрут открывается только после отказа предыдущего.
  Полный неудачный круг получает exponential backoff; входящий слушатель всё
  это время остаётся активным. Новый список устройств от собеседника обновляет
  следующий круг без перезапуска клиента.
- Одна машина, видимая под несколькими адресами (например и как участник твоего
  tailnet, и через share из чужого), считается **одним** устройством, и живой
  маршрут пробуется первым. Служебные узлы `device-of-shared-to-user` из
  списка исключаются.

Селектором может быть и **адрес** устройства — владелец определяется по нему, и
режим пользователя всё равно включается. Это важно: при сыром IP без опознания
владельца клиент остался бы в строгом режиме одного адреса и отверг бы остальные
устройства того же человека.

### Переключение между своими устройствами

Открыл сессию на втором своём устройстве — оно **забирает канал**, а первое
получает кадр `bye` с причиной, показывает
`* this session was taken over by another of your devices` и прекращает попытки
переподключения. Без этого два устройства отбирали бы канал друг у друга каждую
секунду.

Разделение принципиальное: два канала к **одной** машине по-прежнему схлопываются
детерминированным `min(connId)` — иначе стороны выбрали бы разные сокеты и связь
бы развалилась, — а подключение с **другого адреса** трактуется как смена
устройства, и побеждает новое.

### Когда ничего не подключается

Клиент больше не молчит в двух самых частых случаях:

- `* port 4747 is already in use — another tailchat is probably running` —
  забытый экземпляр держит порт, входящие не приходят ни от кого.
- `* cannot resolve "<peer>" — nothing will connect until it does` — опечатка в
  имени либо нет `tailscale` CLI, чтобы опознать пользователя.
- `* rejected inbound from <ip>; expected <peer>` — стучится не тот, кого ты
  указал пиром. Чаще всего это **забытый экземпляр** на чужой машине: он
  переподключается раз в секунду сам, без участия человека. Такая строка
  печатается не чаще раза в минуту на адрес и ничему не мешает.

Если селектор не опознан как пользователь, поведение прежнее: строго тот адрес,
что указан. Так же — если `tailscale` не найден в системе.

История ведётся по-прежнему одним файлом `--log`, поэтому переписка не
разъезжается при смене устройства.

### Если `tailscale` не находится (чаще всего — Windows)

Клиент ищет CLI по известным раскладкам, по `PATH` и по `PATHEXT`: на Windows
это `%ProgramFiles%`, `%ProgramW6432%`, `%ProgramFiles(x86)%` (в том числе
старый каталог `Tailscale IPN`), `%LOCALAPPDATA%`, Scoop и Chocolatey. Если MSI
поставлен с нестандартным `INSTALLDIR`, в чате появится строка вида:

```
* no tailscale command found (13 places tried) — without it there is no verified
  identity and no device roster: put the full path in TAILCHAT_TS_CLI
```

Чат при этом работает — по адресам, — но без проверенной личности, ростера и
whois. Лечится одной переменной; она проверяется раньше всех догадок:

```powershell
setx TAILCHAT_TS_CLI "D:\Tools\Tailscale\tailscale.exe"
```

```bash
export TAILCHAT_TS_CLI=/opt/tailscale/tailscale
```

Если переменная указывает на то, что запустить не удаётся, клиент так и скажет:
`* TAILCHAT_TS_CLI points at <path>, which cannot be run`.

### Если клиент неожиданно остановился

Неожиданная ошибка больше не оставляет за собой ни сломанный терминал, ни
заметку о занятом порте. Клиент возвращает экран (alternate screen, мышь,
bracketed paste, курсор), убирает `listener-<port>.pid` и печатает две строки:

```
tailchat stopped: Error: <что случилось>
the details are in ~/.tailchat/crash.log — worth attaching to a bug report
```

В `crash.log` — время, версия, платформа, аргументы запуска и стек; файл
дописывается и начинается заново, если перерос 64 КБ. Ctrl+Break на Windows
(`SIGBREAK`) и закрытие окна консоли (`SIGHUP`) теперь тоже завершают клиент
чисто — как Ctrl+C.

### Shared node между разными tailnet

Переключать tailnet не нужно. Сторона, которой расшарен узел, подключается к его
shared MagicDNS-имени; например:
```bash
tailchat desktop-example.other-tailnet.ts.net --name Alice
```
Владелец shared node указывает адрес второй машины так, как он отображается
именно в его tailnet (он может отличаться от её собственного tailnet-IP):
```bash
tailchat 100.116.123.83 --name Bob
```
В проверенной паре это mapped-адрес Alice со стороны tailnet Bob; собственный
адрес Alice `100.122.98.16` здесь не подходит. Из-за quarantine обратная
исходящая попытка Bob может не пройти — это нормально: входящего канала
Alice → shared node достаточно для двустороннего чата.

## Опции

Полный список флагов, команд и клавиш всегда доступен в самой программе:
`tailchat --help` при запуске и `/help` внутри чата — они генерируются из одной
таблицы, поэтому не расходятся с кодом.
- `--name <name>`   отображаемое имя на один запуск (по умолчанию: сохранённое в мастере, затем hostname)
- `--log <file>`    файл журнала (по умолчанию: свой файл на разговор в `~/.tailchat`)
- `--no-log`        не вести журнал переписки
- `--bind <ip>`     bind-адрес (по умолчанию авто: tailnet-IP или 0.0.0.0)
- `--menu`          открыть меню выбора пира (набранный пир игнорируется)
- `--no-theme`     монохромный framed TUI (также включается переменной `NO_COLOR`)
- `--no-notify`    отключить desktop-уведомления, звук и fallback terminal bell
- `--files-dir <dir>` каталог для принятых файлов (по умолчанию `~/.tailchat/files`)
- `--max-file <МБ>`   лимит размера файла (по умолчанию 25)
- `--reset`        сбросить настройки и ключи ИИ (config.json, secrets.env) и выйти
- `--mouse`        захватить мышь (клики по превью, прокрутка колесом)
- `--help`          справка

В чате: `/help` — список команд, `/ping` — замер задержки и типа маршрута,
`/status` — статистика сессии и трафика, `/voice [сек]` — запись голосовой заметки
с вейвформом. На macOS по умолчанию используется нативный AVFoundation-helper:
`/voice backend native`; вернуть старый путь — `/voice backend ffmpeg`.
`/voice devices` показывает входы ffmpeg, `/voice device <номер>` фиксирует один.
`/lock` блокирует экран, `/pass <пароль>` устанавливает пароль, `/clear` очищает
переписку, `/logo` рисует логотип, `/holiday` переключает крест, `/quit` выходит.
`/settings` открывает меню языка, темы, журнала, индикатора набора, заставки и AI.
`/peer` переключает собеседника, `/name` — ваше имя, `/lang` — язык интерфейса,
`/theme` — выбор темы, `/logs on|off` — журнал переписки.
Ctrl-C, Ctrl+Break и закрытие окна консоли завершают клиент и восстанавливают
терминал. Версия показывается в приветственной строке при запуске.

### Termux, Android

Быстрая установка одной командой (Node, git, снятие мёртвого `tailscale`,
симлинк на обёртку с `termux-wake-lock`, `termux-api`,
`termux-setup-storage`) — [`termux-wrapper/install.sh`](../termux-wrapper/README.md),
безопасен при повторном запуске (заодно и обновляет). Ниже — то же самое
руками и почему каждый шаг именно такой.

На телефоне работает приложение Tailscale, и **CLI в Termux не нужен** — более
того, он вредит: `pkg install tailscale` кладёт двоичный файл, которому не с чем
разговаривать (своего `tailscaled` в Termux не поднять, к сокету приложения
доступа нет). Каждый вызов падает. До `0.46.4` клиент считал наличие файла
достаточным поводом спрашивать у него, кому принадлежит входящий адрес, — и
поскольку ответа не было никогда, **отклонял все входящие**. Сейчас мёртвый CLI
равен отсутствующему, но держать его всё равно незачем:

```
pkg uninstall tailscale
```

Что остаётся от приложения Tailscale и чего достаточно: маршрутизация и **DNS**.
Полное имя MagicDNS резолвится обычным `dns.lookup`, без всякого CLI — значит
звать собеседника надо так:

```
tailchat desktop-example.mynet.ts.net
```

Имя лучше адреса: адрес у собеседника поменяется, имя нет. Если в приложении
выключено «Use Tailscale DNS», имя не разрешится — тогда один раз по `100.x`.
После первого удачного сеанса устройства собеседника попадают в ростер, и дальше
годится и короткое имя, и логин.

Чего на телефоне не будет без CLI: режима логина (`tailchat user@example.com` с
первого запуска), списка устройств собеседника и проверки нового адреса через
демон. Внешними воротами остаются ACL тайлнета.

**Запуск.** У пакета две точки входа, и это не прихоть:

| команда | шебанг | где нужна |
| --- | --- | --- |
| `tailchat` | `#!/usr/bin/env node` | macOS, Linux, **Windows** (npm делает там `.cmd`-обёртку по шебангу и зовёт node) |
| `tailchat-sh` | `#!/bin/sh` | Android |

На Android нет `/usr` вообще, поэтому `/usr/bin/env` не существует. В
интерактивном Termux это скрыто: `LD_PRELOAD=libtermux-exec.so` переписывает
шебанги на лету. Но вне такой оболочки — ssh, cron, скрипт, вызов из другого
приложения — ядро не находит интерпретатор, и запуск падает с
`env: 'node': Permission denied` (rc=126). Отсюда и «`tailchat` не запускается, а
`node bin/tailchat.js` запускается».

`/bin/sh` на Android есть (символическая ссылка на `/system/bin/sh`), поэтому
`tailchat-sh` работает в любом контексте. Сделать его **единственной** точкой
входа нельзя: на Windows npm построил бы обёртку, зовущую `sh`, и сломал бы тех,
у кого его нет. Поэтому обе.

Чтобы на телефоне работало привычное короткое имя, ссылка ставится вручную —
`npm install` её не трогает, так что `/update` её не потеряет:

```
ln -sf ../lib/node_modules/tailchat/bin/tailchat $PREFIX/bin/tailchat
```

### Выделение текста мышью

По умолчанию мышь **отпущена** терминалу: родное выделение и копирование
работают сразу. Команда `/mouse` (или клавиша `Ctrl+T`) захватывает её обратно —
тогда перетаскивание выделяет и копирует строки целиком (в том числе за краем
экрана), клик по ссылке открывает браузер, а копия берётся из текста сообщения,
а не из перенесённых строк. Флаг `--mouse` запускает клиент сразу с захватом.

С той же захваченной мышью работает и полоса контактов под черновиком: клик по
контакту открывает переписку с ним, а колесо над полосой прокручивает сам
ростер — полоса занимает не больше трёх строк, а контактов обычно больше.
Попадание считается по самому контакту: клик по уже открытому контакту ничего не
меняет, клик по промежутку между контактами — тоже. Прокрутка полосы живёт до
первого переключения: как только разговор сменился, окно снова следует за
открытым контактом.

Многострочная вставка сворачивается в черновике в одну строку
«вставлено строк: N»; `Ctrl+X` разворачивает и сворачивает её обратно,
`Enter` отправляет полный текст.


Многие терминалы позволяют выделять с зажатым `Shift` (в iTerm2 — `Option`), не
отпуская мышь совсем.

Прокрутка истории: колесо мыши/трекпад, `Shift+↑`/`Shift+↓` — построчно,
`PgUp`/`PgDn` — постранично (колесо — 3 строки за щелчок), а при пустом черновике
просто `↑`/`↓` — удобно на телефоне, где нет `PgUp`/`PgDn`. На Mac-клавиатуре без numpad `PgUp`/`PgDn` — это
`Fn+↑`/`Fn+↓`. Пока история прокручена вверх, вид в конец **не** сбрасывают
служебные строки (`connected`, `listening`); а вот новое сообщение — своё или
чужое — всегда возвращает вид вниз, чтобы его нельзя было пропустить, читая
историю.

И ещё одно возвращает: **первый набранный символ**. Читать историю — это
намеренное действие, и прокрутка сохраняется, пока вы только читаете. Но как
только в черновике появляется буква или туда попадает вставка, вид уходит в
конец: ответ, написанный на экран, где не видно последнего сообщения, — это
способ ответить на одно и то же дважды.

Черновик — **одна строка**, и растёт по мере текста до пяти. Пустого ряда под
ним больше нет: рамка идёт сразу за строкой ввода.

## Расписки о доставке

У своих сообщений слева от имени стоит маркер:

| маркер | значение |
|---|---|
| `⧗` | в офлайн-очереди, ещё не отправлено |
| `→` | записано в сокет, подтверждения нет |
| `✓` | доставлено клиенту пира |
| `✓✓` | пир прочитал — его окно было в фокусе |

`✓` означает доставку клиенту — это факт транспорта. `✓✓` означает, что человек
мог увидеть сообщение, и ставится **только по доказательству**: терминал сообщил
о фокусе окна либо получатель нажал клавишу. Никаких допущений.

Часть терминалов (в том числе Termux на Android) не сообщают о фокусе вообще. Там
клиент переходит в урезанный режим: присутствие не отправляется, а `✓✓` приходит
по нажатию клавиш. Определяется это по факту получения событий, а не по имени
системы, и собеседник узнаёт об ограничении строкой
`* <имя> runs a terminal that cannot report focus` — поэтому отсутствие `✓✓`
никогда не остаётся загадкой. Маркер меняется на месте и не
сдвигает строку. Старый клиент без поддержки расписок просто не даст `✓` —
сообщения при этом доставляются как обычно.

## Файлы и картинки

```
/send ~/photo.jpg     отправить файл (нужно живое соединение)
/send "C:\путь\с пробелами.png"   кавычки снимаются автоматически
/paste                отправить картинку из буфера обмена (или Ctrl+V)
/files                список файлов сессии: принятые и отправленные, с номерами
/open 3               открыть файл сессии системным просмотрщиком
/open                 открыть последний файл — принятый или отправленный
```

Важно: **перетащить файл в терминал и нажать Enter недостаточно** — терминал
вставит путь, и он уйдёт обычным текстовым сообщением. Нужен именно `/send`
перед путём; если отправить путь текстом, клиент подскажет об этом отправителю.
Команды терпимы к мелким опечаткам: лишний пробел после слэша (`/ open 1`) и
кавычки вокруг пути обрабатываются. Если у собеседника версия старше `0.5.0`,
`/send` откажется работать и предложит ему обновиться, вместо того чтобы
отправлять кадры, которые тот молча выбросит.

Картинка передаётся как обычный файл, а `/open` отдаёт её Preview на macOS,
`xdg-open` на Linux, `start` на Windows. Инлайн-отрисовка в терминале не
делается сознательно: пиксельные escape-последовательности не согласуются с
буфером ячеек `blessed`, а единого протокола для Ghostty (Kitty graphics) и
Windows Terminal (Sixel) всё равно нет.

### Скриншот из буфера обмена

`Ctrl+V` в поле ввода отправляет картинку из буфера обмена — удобно для
скриншотов (`Cmd+Shift+Ctrl+4` на macOS кладёт снимок сразу в буфер). Та же
операция доступна командой `/paste`.

Читается без внешних зависимостей: `osascript` на macOS, PowerShell
(`Clipboard::GetImage`) на Windows, `wl-paste`/`xclip` на Linux. Если в буфере
нет картинки, клиент честно сообщит об этом и ничего не отправит; пустой
результат тоже отбрасывается, а не уходит как файл нулевого размера.

На Windows Terminal `Ctrl+V` по умолчанию перехватывается терминалом как
вставка текста и до приложения не доходит — там надёжнее команда `/paste`.

Приём защищён: имя схлопывается до basename, поэтому `../../.ssh/authorized_keys`
не покидает каталог загрузок; целостность проверяется `sha256`; превышение лимита
(`--max-file`, по умолчанию 25 МБ) и битая передача не оставляют файла на диске;
совпадение имени не перезаписывает существующий файл, а добавляет ` (2)`.
Каталог по умолчанию `~/.tailchat/files/` с правами `0700`, файлы — `0600`.

## Офлайн-очередь

Если пир недоступен, сообщение не теряется: оно помечается `⧗`, встаёт в
очередь и уходит автоматически при восстановлении связи — по порядку и с
временем **написания**, а не доставки. TUI подтверждает доставку строкой
`* delivered N queued message(s)`.

Очередь хранится на диске (`~/.tailchat/outbox-<peer>-<hash>.json`, права
`0600`), поэтому переживает перезапуск клиента и падение процесса: при старте
появится строка `* N message(s) still queued from a previous run`. Файл
переписывается атомарно через `rename` и удаляется после доставки. Для каждого
пира своя очередь — сообщения не путаются между собеседниками. Размер ограничен
500 сообщениями, при переполнении вытесняются самые старые.

## Индикатор присутствия

Статус справа в header показывает, что происходит у собеседника:

| статус | значение |
|---|---|
| `● ACTIVE` | окно чата активно, он смотрит |
| `◐ IDLE` | окно не в фокусе, но переключился он только что |
| `○ AWAY` | окно не в фокусе дольше заданной паузы (по умолчанию 15 минут) |
| `● ONLINE` | связь есть, присутствие неизвестно (клиент старее `0.10.0`) |
| `◌ WAITING` | слушаем и ждём; прямо сейчас никуда не звоним |
| `◌ CONNECTING` | звонок открыт именно в эту секунду |
| `◌ RECONNECTING` | связь потеряна, идут попытки переподключения |

Разделение `IDLE`/`AWAY` не косметика: неактивное окно и отсутствие человека —
разные вещи. Чат может лежать на втором мониторе, пока собеседник работает в
браузере: он за компьютером и увидит сообщение. Поэтому потеря фокуса сразу даёт
только `IDLE`, а `AWAY` появляется лишь после паузы без фокуса — по умолчанию
15 минут, настраивается командой `/saver after <минуты>` (см. «Заставка» ниже:
это тот же таймер).

Приоритет намеренный: потеря связи важнее всего, затем набор текста, и лишь потом
присутствие — так `○ AWAY` никогда не маскирует оборвавшийся канал. Клиент версии
`0.10.x` умел сообщать только «окно неактивно»; такое сообщение трактуется как
`IDLE`, потому что о длительности он ничего не знает.

## Позвать собеседника

`/wake` посылает настойчивый сигнал: у собеседника появляется строка
`* ⚠ <имя> is asking for your attention`, звучит terminal bell и, если
уведомления не отключены, приходит системное уведомление. Работает и когда его
окно активно — сигнал явный и редкий.

Чтобы зажатый Enter не превратился в шквал звонков, действует пауза 10 секунд:
повторный вызов внутри окна отвечает `* wait Ns before nudging again`. Окно
считается от последней успешной отправки, поэтому отклонённые попытки его не
продлевают.

## Вставка многострочного текста

Вставленный текст приводится в порядок: подряд идущие пустые строки схлопываются
в одну, хвостовые пробелы срезаются, пустые строки по краям убираются. Вывод
терминала полон пустот, которые в переписке не значат ничего и просто выдавливают
разговор с экрана.

Терминалы без поддержки скобочной вставки (Windows Terminal через RDP в их
числе) отдают вставку как обычные нажатия — и каждый перевод строки срабатывал
как Enter, разрывая вставленный блок на десяток сообщений.

Клиент отличает вставку от набора по форме порции. Человек, нажавший Enter, на
этом ввод и заканчивает — терминал не может знать, что он напечатает следом,
поэтому текст **после** перевода строки мог прийти только вместе с ним. Без
перевода строки выдаёт размер: tty отдаёт нажатия по одному, и шестнадцать
символов в одной порции никто не набирает.

Второе правило и делает перетаскивание рабочим там, где терминал не размечает
вставку: путь приходит одной порцией без перевода строки. Если поле пустое,
файл уходит сразу; если в поле уже что-то набрано, путь просто вставляется —
значит, вы пишете сообщение, а не отправляете файл.

## Автодополнение команд

Наберите `/` — под перепиской появится список команд с описанием. Он сужается
по мере набора и понимает как полное имя, так и короткую форму. `Вверх`/`Вниз`
двигают выбор, окно прокручивается за ним и показывает `… +N` для остальных,
`Tab` подставляет команду.

`Enter` при открытом меню тоже подставляет выбранное — то, что обещает
подсвеченная строка. Отправить в чат «/» он не может: это была бы опечатка, а
не сообщение. Когда команда набрана целиком (`/help` или `/h`), подставлять
нечего и `Enter` её выполняет. На обычном тексте меню не появляется, и `Enter`
работает как всегда.

## Перетаскивание файлов

Перетащите файл в окно — он уйдёт файлом, а не строкой с путём. Терминал
доставляет перетаскивание как вставку пути, поэтому клиент разбирает все три
формы записи: экранированные пробелы (macOS), кавычки (Windows) и список по
строкам, когда файлов несколько.

Разделение по пробелам применяется только если **каждая** часть — существующий
файл. Иначе обычная фраза с именем файла превратилась бы в передачу, которой
никто не просил.

Какое соглашение применил терминал, клиент не угадывает: он проверяет оба
прочтения пути — как есть и со снятым экранированием — и берёт то, которое
указывает на существующий файл. Слепое снятие экранирования превратило бы
`C:\Users\x\a.png` в `C:Usersxa.png`. Это же разрешение работает и для
`/send`, поэтому файл можно перетащить как в пустое поле, так и прямо в команду.

## Устройство собеседника

В шапке рядом с именем видно, с какой машины он отвечает: `Alice ↔ Roman @
desktop-example`. Имя берётся у локального демона Tailscale по адресу подключения,
подделать его нельзя — в отличие от `--name`, который каждый задаёт себе сам.

У узла, расшаренного из **чужого** tailnet, Tailscale намеренно скрывает имя
машины: оно пустое, а служебное — заглушка `device-of-shared-to-user`.
В этом случае клиент прямо говорит, что имени нет, вместо того чтобы молчать
или выдавать заглушку за название устройства. Если человек перешёл на другое устройство, об этом
появляется отдельная строка.

У узла без разрешаемого логина (например, тот же shared node) ростер не
даёт вообще ничего: собеседник виден под тем, что объявляет его собственный
клиент — `args.name`, который по умолчанию равен имени машины и часто так и не
был заменён. Отсюда `desktop-ag8b8u4` вместо человеческого имени.
`/nick <имя>` даёт локальное прозвище — только на этом экране, собеседнику оно
никогда не уходит и не зависит от его логина: `/nick` без аргумента показывает
текущее, `/nick clear` возвращает автоматическое имя. Хранится в той же папке
состояния, что и последнее устройство собеседника, и переживает
переподключение — запоминание нового устройства эту запись не трогает.
`/history` тоже показывает текущее прозвище, а не то имя, под которым строки
были когда-то записаны в лог: подменяется только поле отправителя в начале
строки (`[HH:MM] имя: …`), сам файл на диске остаётся как есть.

## Обновление

При запуске клиент сравнивает свою версию с той, что работала из этой копии в
прошлый раз, и показывает, **что изменилось** — только строки `feat:` и `fix:`
из истории коммитов. Служебные (`chore`, `test`, `refactor`) отфильтрованы: они
ничего не меняют для того, кто читает чат, и хоронили бы те две строки, ради
которых список и нужен.

Отметка о прошлом запуске лежит на диске рядом с остальным состоянием, а не
передаётся от процесса к процессу. Поэтому обычный `git pull && npm install`
отчитывается точно так же, как `/update`.

Если собеседник отстал по версии, ему прилетает явная просьба обновиться — он
увидит её у себя в переписке, а не будет гадать по номеру версии. Команда
`/update` сначала получает `origin/main`, сохраняет локальные правки и
неотслеживаемые файлы в stash, переводит **фактически запущенную копию** на
полученный коммит, выполняет `npm install` и сразу запускает tailchat заново —
с тем же адресом собеседника и теми же флагами. Поэтому старый глобальный
`npm link` обновляет свой checkout, даже если рядом уже клонировали новую копию.
Перед командами updater печатает `tailchat checkout: <путь>`: это именно та
копия, из которой запущен процесс, а не текущий каталог открытой оболочки.

Устаревшая сторона получает не короткую служебную строку, а полный баннер;
сравнение `hello` и отдельный `update`-кадр схлопываются, поэтому он появляется
один раз:
Когда версия собеседника новее локальной, в верхней строке интерфейса остаётся
`update!` до перезапуска после `/update`; баннер в переписке по-прежнему
показывается один раз.

```text
********************************************************
* ТРЕБУЕТСЯ ОБНОВЛЕНИЕ TAILCHAT
* у вас: v0.50.1 | Roman: v0.50.2
* запустите /update сейчас
* локальные правки сохранятся; зависимости установятся; tailchat перезапустится
********************************************************
```

Обновляющаяся сторона тоже видит свой баннер ровно один раз — и в чате через
`/update`, и в терминале через `tailchat --update`:

```text
********************************************************
* ЗАПУСКАЕТСЯ ЛОКАЛЬНОЕ ОБНОВЛЕНИЕ TAILCHAT
* текущая версия: v0.50.2
* рабочая копия: /Users/alex/tailchat
* сохраняю правки; синхронизирую main; ставлю зависимости; перезапускаю один раз
********************************************************
```

Интерфейс закрывается **до** обновления: git и npm пишут в тот же терминал, и
поверх полуразобранного TUI их вывод не прочитать. Новая версия запускается
дочерним процессом на том же терминале — заменить себя, как это делает `execve`,
Node не умеет, а отдать терминал отсоединённому процессу нельзя: оболочка
заберёт его обратно, и оба начнут читать одну клавиатуру.

Расплата — один ждущий родитель на каждое обновление. Поэтому цепочка
ограничена тремя: дальше обновление проходит, но перезапуск остаётся за вами.
Без этого предела шесть обновлений за день дают семь процессов.

Сеть проверяется до stash: неудачный `git fetch` вообще не трогает локальную
работу. После успешного fetch обновление не блокируют изменённый
`package-lock.json`, разошедшаяся ветка или другие локальные файлы. Правки и
неотслеживаемые файлы остаются в `git stash list` с пометкой
`tailchat auto-update`, а расходящиеся локальные коммиты — в ветке
`tailchat-update-backup-<sha>`. Рабочая копия точно совпадает с полученным
`origin/main`.

## История

При подключении клиент сам показывает хвост переписки — до 20 последних
сообщений из файла журнала (многострочная вставка или ASCII-арт по-прежнему
одно сообщение, а не несколько), под заголовком «недавняя история» и в тех же
цветах, что у живого разговора (у каждого свой цвет, а не один тусклый
оттенок на весь блок): достаточно, чтобы вспомнить, на чём остановились, но
не экран целиком.
`/history` копает глубже — до 100 сообщений — и, если часть из них уже была
отправлена или получена в текущем сеансе, отделяет её от более старых заголовком
«since you connected»: старое и новое не сливаются в одну стену текста.

## Язык интерфейса

Поддерживаются английский, русский и французский. Выбор при первом запуске
запоминается в `~/.tailchat/config.json`; язык окружения (`LANG`, `LC_ALL`,
`LC_MESSAGES`) остаётся запасным, а флаг или переменная переопределяют всё:

```bash
node src/cli.js lit --lang ru
TAILCHAT_LANG=fr node src/cli.js lit
```

Поддержку клиент выясняет у терминала стандартным запросом `DECRQM` и ждёт
ответа до 800 мс: локальный терминал отвечает за микросекунды, а через RDP или
SSH ответ может задержаться, и короткое окно понизило бы вполне способный
терминал до урезанного режима. Полное ожидание платит только тот, кто не
отвечает вовсе, и только один раз при запуске.

Проверить состояние в любой момент можно командой `/version` — она показывает
не только версии, но и кто из двоих сообщает фокус:

```
* your terminal reports focus: yes
* termux reports focus: yes
```

Строка о неспособности терминала печатается один раз за запуск, но если
возможность появилась, клиент об этом скажет — иначе старое утверждение
осталось бы на экране противоречить шапке.

Молчание терминала на запрос — это **третий** ответ, отличный от «не умею».
Windows Terminal и Warp сообщают фокус прекрасно, но `DECRQM` игнорируют, и
чтение молчания как отказа заставляло собеседника считать человека невидимым.
Поэтому молчание разрешается по платформе: Termux — единственная измеренная
среда, которая событий фокуса не присылает вовсе, и она сама сообщает о себе
через `TERMUX_VERSION`. Везде остальном молчание значит «скорее всего умеет», а
первое настоящее событие это подтверждает.

Возможность объявляется собеседнику не только при подключении. Проба может
промахнуться — терминал вправе ответить слишком поздно или не ответить вовсе, —
а настоящее событие фокуса доказывает поддержку окончательно. Поэтому первое же
такое событие переобъявляет возможность, и присутствие начинает доходить, даже
если в начале сессии ответа не было.

Асимметрия здесь нормальна: если фокус не сообщает **его** терминал, вы не
видите его присутствия, но ваше до него доходит по-прежнему.

Статус-токены в шапке (`ONLINE`, `ACTIVE`, `IDLE`, `AWAY`) намеренно остаются
английскими: их переводы вдвое длиннее и ломают ширину строки, а как индикаторы
они читаются одинаково на любом языке. Имена команд (`/help`) тоже не
переводятся — их набирают руками, и они должны быть стабильны.

## Подключение по имени без CLI tailscale

В Termux нет бинарника `tailscale`, поэтому превратить логин в список устройств
там нечем — а именно это позволяет писать `tailchat roman` вместо адреса.
MagicDNS в Termux при этом работает, так что по **имени устройства** подключение
возможно всегда.

Логин закрывается иначе: тот, у кого CLI есть, сообщает по связи, какие машины
ему принадлежат, и собеседник это запоминает в `~/.tailchat/roster.json`. После
одного успешного подключения по адресу или имени устройства имя пользователя
начинает работать и там, где CLI нет:

```
* alex is alex@example.com — 20 device(s) remembered
* connected to mac
```

Запоминается и **имя, под которым человек виден в чате**: в шапке написано
`godsheep`, поэтому именно это собеседник набирает первым, хотя Tailscale о таком
имени ничего не знает. Работают все четыре формы: логин, его часть до `@`, имя
устройства и имя из чата.

Если имя не опознано, клиент не отмалчивается, а перечисляет то, что знает:

```
* no tailscale CLI here, and кто-то is not a remembered peer
*   alex@example.com, alex, macbook-alex, phone-roman
* connect once by address or device name, and the name will work next time
```

Первым в списке идёт сама машина: без этого собеседнику некуда звонить обратно.
Устройства, называющие себя `localhost` (так делает Android), остаются
отдельными записями — группировка по имени хоста склеила бы разные машины и
спрятала нужный адрес.

Реестр — удобство, а не право доступа. Когда CLI есть, заявленный логин
проверяется у демона, и несовпадение отбрасывается. Где CLI нет, проверить
нечем, поэтому шире запомненного набора адресов клиент не пускает никого, а
внешним рубежом остаётся ACL самого tailnet.

## Оформление сообщений

Разметка взята из Telegram, чтобы её не надо было учить заново: `**жирный**` и
`*жирный*`, `__подчёркнутый__`, `` `код` ``, блоки в тройных кавычках, заголовки
`#`, списки `- `/`* `/`+ ` и цитаты `> `.

Блок кода подсвечивается по языку из ограды: имя языка печатается над блоком, а
ключевые слова, строки, числа, операторы и комментарии получают свои цвета. Знает
`sh`/`bash`/`zsh`, `js`/`ts`, `py`, `json`.

Язык **не угадывается**. Я попробовал определять его по первому слову и получил
подпись `shell` над куском JavaScript: `export` и `function` есть в обоих списках.
Поэтому ярлык показывается только тот, который написали руками, а блок без языка
получает подсветку того, с чем согласны все языки: строки в кавычках, числа,
комментарий в начале строки и операторы, которые не бывают частью пути (`&&`,
`||`, `=>`, `===`, `!==`). Ключевые слова без языка не красятся вовсе.

Комментарий требует `# ` с пробелом или `//` в начале строки — иначе приватное
поле `this.#count` и `https://` в ссылке считались бы комментарием.

Это не разборщик, а несколько честных правил: сообщение в чате — обрывок, половина
конвейера или одна функция, и всё, что требует настоящего контекста, ошибалось бы
чаще. Операторы заданы по языку: в оболочке `/` — это путь, а `--x` — флаг, и
красить их незачем.

Обернуть уже набранное в блок — `Ctrl+B`, язык угадывается по первому слову.
Отправить блоком сразу — `/code <код>`: код едет аргументом, потому что команда
занимает весь черновик и оборачивать ей было бы нечего.

Чтобы набрать блок руками, нужен перенос строки внутри черновика: `Alt+Enter` или
`Ctrl+J`. `Enter` по-прежнему только отправляет. Alt+Enter приходит от терминала
как `ESC` плюс `CR`, поэтому склеивается обратно по времени; `Ctrl+J` приходит
отдельной клавишей и трюка не требует.

Курсива и зачёркивания нет намеренно: blessed вырезает сырые ANSI-коды из
содержимого, поэтому `\x1b[3m` до терминала не доходит вовсе. Обещать то, что не
отрисуется, хуже, чем не обещать.

Жирный — только `**двойная звёздочка**`. Одиночную форму и `__подчёркивание__`
я пробовал и убрал: в чате про оболочку и Python `'*.db*'` — это глоб, а
`__init__` — имя метода, и обе формы их съедали. Потерянный символ во вставленной
команде хуже, чем отсутствующий способ выделить текст. Список команд (`/help`) эти формы перечисляет, чтобы их не надо было
угадывать.

Разметка нужна явная: строка «тест форматирования: node test.js» останется
обычным текстом, потому что в ней нет ни обратных кавычек, ни решёток. Дефис
внутри предложения списком не считается — только в начале строки.

Маркеры списка и цитаты окрашиваются, но **не удаляются**: вставленный отчёт
должен пережить обратное копирование. Внутри блока кода
разметка не толкуется — там `**` и `#` остаются символами, а отступы сохраняются
как есть, потому что в коде они значат смысл. В монохромном режиме символы
разметки убираются, но цвет не добавляется.

## Акценты в сообщении

Имя отправителя выделено цветом: своё — зелёный, чужое — голубой. Внутри текста
части различаются акцентами: время серое, ссылки синие с подчёркиванием, цитата —
с голубовато-серым тоном, встроенный код бирюзовый.

Клик по ссылке открывает её в браузере тем же путём, что `/open` для файлов;
голый `www.…` дополняется схемой `https://`.

На macOS сочетания показываются и работают с `⌘` вместо `Ctrl` — терминал
доставляет её как `meta`, поэтому клиент принимает и то и другое.

## Картинки прямо в переписке

Принятый или отправленный снимок рисуется маленьким блоком прямо в переписке —
половинчатыми символами, верхняя и нижняя половина клетки разными цветами.
PNG разбирается самим клиентом; остальные форматы идут через то, что есть на
машине (`sips` на маке, `ffmpeg` на Termux, PowerShell/System.Drawing на
Windows). Нет инструмента или файл нечитаем —
превью просто нет, передача от этого не страдает. В монохроме вместо цветов —
градация яркости. Клик по превью открывает файл тем же способом, что `/open`.

Превью стоит дёшево при прокрутке, и это не само собой: цвет в нём назван
номером палитры терминала и только там, где он меняется, а не в каждой клетке
дважды. Blessed заново разбирает каждый escape-код в видимой части кадра — и,
пока это не было исправлено, весь текст переписки целиком на каждом кадре, — так
что картинка в переписке когда-то делала один щелчок колеса дороже всего
остального кадра. Клик по превью тоже больше не теряется: где что лежит,
считается по самим строкам истории, а не по номеру строки, запомненному при
добавлении, — история подрезает свою голову, `/clear` опустошает её целиком, и
запомненный номер после этого показывал не туда.

## Меню команд

Список дополнения под `/` отчёркнут сверху собственной рамкой: имя и
пояснение — разными цветами, выбранная строка — инверсией, счётчик
`commands 2/17` показывает, сколько ещё ниже. Больше не сливается с перепиской.

## Цвета в коде

Подсветка кода различает тринадцать видов: комментарии, строки и экранирования
в них, числа, ключевые слова, встроенные значения, имена в позиции вызова,
операторы, скобки, переменные, члены после точки, типы/классы и флаги. Переменная
больше не белая, а зелёная, и не ещё один синий — поэтому `const a` читается
двумя цветами, а не одним. Жирные только ключевые слова: `const`, `function`,
`import` — первые слова строки, на которые глаз падает первым, как в VS Code.
Аргументы shell — нейтрального цвета, поэтому команда, флаги, пути и каналы
вокруг них читаются по отдельности, а не одной зелёной стеной. Блок кода лежит
на тёмной подложке, поэтому виден целиком даже там, где шрифт не умеет жирный.

## Справка


`/help` показывает команды — две колонки, раздел отчёркнут, имя команды цветом,
описание переносится под свою колонку. Остальное по запросу, чтобы не вываливать
полсотни строк разом:

    /help клавиши      /help keys
    /help флаги        /help flags
    /help всё          /help all

Слово понимается на любом из трёх языков независимо от языка интерфейса: человек
набирает то, на чём думает.

## Статус — по активности, не по фокусу

`ACTIVE` значит «человек за клавиатурой прямо сейчас», а не «окно впереди».
Окно в фокусе, но мышь не двигается и клавиши не нажимаются — через полминуту
статус становится `IDLE`, через заданную `/saver after` паузу (по умолчанию
15 минут) — `AWAY`. Любое нажатие или движение мыши сбрасывает отсчёт. Потеря
фокуса, как и раньше, сразу даёт `IDLE`.

## Файлы: картинка, значок, клик

Принятый или отправленный файл показывается в переписке: картинка — блоком
цветных половинчатых клеток, любой другой файл — карточкой с расширением, в том
же стиле. Сверху и снизу — пустая строка, чтобы превью не теснило текст. Клик
по превью или карточке открывает файл; вставленная из буфера картинка тоже
открывается, её временная копия теперь не удаляется.

## Индикатор набора
 и каретка

Набор показывается **внизу, на разделителе черновика**, а не в шапке: это
мимолётное событие, а шапка для того, что длится. Свой набор виден так же, как
чужой: пока печатаешь — `Alice typing`. Если одновременно печатают двое или все
трое, имена не вытесняют друг друга: `Alice + Roman typing` или
`Alice + Roman + tailik typing`. Шапка продолжает показывать присутствие.

Положение каретки читается **из самого blessed**: он переносит по словам, а не
каждые N ячеек, и подсчёт ячеек оставлял каретку на первой строке вставленного
абзаца, пока набор шёл в конце. Теперь используется его же список обёрнутых
строк (`ftor`, а не `rtof` — на этой путанице я и споткнулся).

## Неверный адрес

Опечатка в tailnet-адресе выглядела точно так же, как выключенный собеседник:
бесконечное ожидание и никаких объяснений. Теперь клиент спрашивает у
локального демона, существует ли такой узел вообще, и не молчит:

```
* 100.72.63.4 is not a device in your tailnet — nothing will answer there
* did you mean: 100.72.63.41 (phone-roman)
* check it with: tailscale status
```

Подсказка ищет узлы, чей адрес отличается от набранного не более чем на две
правки. Служебные заглушки из чужих tailnet в подсказки не попадают — к ним
всё равно не подключиться. Верный адрес ложных тревог не вызывает.

## Индикатор набора и отправки

Полоса света идёт по всей надписи с именами тех, кто сейчас набирает, — так же,
как в omp: мягкая косинусная волна проходит по буквам слева направо со скоростью
одна клетка за кадр (30 кадров в секунду), уходит за край и ждёт в темноте до
следующего прохода. Для `Roman typing` проход короткий; для
`Alice + Roman + tailik typing` длиннее, но скорость та же. Примерно треть
цикла надпись ровно тлеет: эта пауза читается как дыхание, а полоса, которая
тут же возвращается к началу, — как вращающийся столб парикмахерской.

Цвет — от тёмно-зелёного покоя через яркий к почти белому гребню, гребень ещё и
полужирный. Оттенки названы **номерами клеток** палитры xterm-256, а не hex:
blessed пересчитывает hex по своей таблице, и тёмный конец зелёного скатывался
то в серый (236), то в бирюзовый (23) — надпись в покое выходила не того цвета.

Тот же перелив показывает **отправку файла**: `sending <имя>` на том же
разделителе, пока байты действительно идут. До 0.42.30 показывать там было
нечего — все куски файла заливались в буфер сокета одним синхронным циклом
(25 МБ = 534 куска и 33 МБ base64 за 23 мс), событийный цикл не получал ни
одного такта, а «отправлено» печаталось, когда байты ещё стояли в очереди.
Теперь темп задаёт сокет: цикл ждёт, когда буфер полон, поэтому и такты для
анимации есть, и «отправлено» означает, что байты ушли. Во время передачи
`sending <имя>` временно занимает разделитель, но набор участников продолжает
храниться и сразу возвращается после отправки. Передачи идут по очереди, а не
вперемешку.

Если собеседник уходит посреди передачи (`/quit` — это FIN), «отправлено» не
печатается: приходит `sending <имя> broke off — the connection went away`.
Отдельная проверка на **записываемость** сокета, а не на «онлайн»: после FIN
Node закрывает и нашу сторону, сокет перестаёт принимать байты сразу, а событие
`close` (и вместе с ним «связь пропала») случается позже. До 0.42.31 в это окно
цикл прокручивал остаток файла на микрозадачах, не отдавая такт событийному
циклу, и печатал «отправлено 20 МБ», когда до собеседника дошло 6.9. Замерено.

Полоса движется сама, и экран не перерисовывается, когда не происходит ничего.

## Как выделить и скопировать

Пока мышь захвачена (`/mouse`), протащите её по переписке. Выделяются строки
целиком, у краёв экран прокручивается сам — можно взять кусок длиннее одного
экрана. На отпускании выделенное уходит в системный буфер: `pbcopy` на маке,
`clip` на Windows, `xclip`/`wl-copy` на Linux, `termux-clipboard-set` на
телефоне. Клиент говорит, сколько строк скопировал.

Терминал так не умеет: приложение занимает альтернативный экран, и терминал
видит только текущую страницу. Отпустите мышь (`/mouse`), если хотите выделять
по-старому, терминалом.

## Запуск через обёртку

`bin/tailchat.js` запускает клиент в цикле — одна обёртка на всех ОС.
`/update` теперь не заводит потомка: клиент выходит с кодом 75, и обёртка
поднимает новую версию, когда старый процесс уже закончился. Раньше каждое
обновление оставляло ждущего родителя — шесть обновлений давали цепочку из семи
процессов. Любой другой код выхода цикл не повторяет.

    npm link      # tailchat окажется в PATH
    tailchat lit --name Me

Прямой `node src/cli.js` тоже работает, только тогда обновление по-прежнему
запускает потомка и ограничено тремя вложенностями.

## Куда падают принятые файлы

На компьютере — в `~/.tailchat/files`. На Android — в общую папку загрузок
(`/sdcard/Download/tailchat`), потому что домашний каталог Termux закрыт от
других приложений: снимок, сохранённый туда, не виден ни галерее, ни плееру, ни
кнопке «поделиться». Клиент перебирает `~/storage/shared/Download`,
`/sdcard/Download`, `/storage/emulated/0/Download` и берёт первую, куда
действительно пишет; если общей памяти нет — остаётся домашний каталог.

Проверка именно на запись, а не на существование: `termux-setup-storage` часто
доделан наполовину, и `~/storage/downloads` оказывается обычной личной папкой —
на вид опрятной и такой же невидимой.

Состояние — очередь отправки, реестр устройств, pid-файл — туда не уезжает
никогда: для него есть `--state-dir` (по умолчанию `~/.tailchat`). Раньше он
выводился из `--files-dir`, теперь это отдельный флаг.

## Уведомления на телефоне

На Termux уведомления идут через `termux-notification` из пакета `termux-api`:

    pkg install termux-api

Тогда `--no-notify` больше не нужен. Уведомление всегда одно и то же по
идентификатору, поэтому серия сообщений заменяет предыдущее, а не копится в
шторке. Без `termux-api` клиент молчит и просто звонит в терминал.

## Как часто он стучится

Внутри одного круга клиент без пауз перебирает все известные маршруты
собеседника. Если не сработал ни один, задержка между полными кругами
удваивается: 1, 2, 4, 8, 16, 30 секунд и дальше по 30. Раньше это была секунда
после каждой отдельной попытки — 3600 обращений в час к выключенной машине,
причём рабочий второй адрес ждал за мёртвым первым.

Замедление безопасно именно из-за симметрии: **слушатель не спит никогда**,
поэтому вернувшийся собеседник дозванивается сам, с первой попытки, не дожидаясь
нашей. Проверено: пока звонки замедлились до 4 секунд, появившийся пир установил
связь за 18 мс. Задержка сбрасывается на секунду от любого признака жизни —
установленного канала или входящего звонка.

Свои звонки при этом нужны только для одного случая: когда вернулись **мы**, а
собеседник всё это время работал и о нашем возвращении не знает.

## Если порт занят

Забытый экземпляр, держащий порт, — самая частая причина «не подключается».
Клиент, которому удалось занять порт, оставляет свой pid рядом с остальным
состоянием, а тот, которому не удалось, читает эту заметку и называет виновника:

```
* port 4747 is held by another tailchat, pid 31210
* close that window, or end it with: kill 31210
```

Заметка убирается при выходе, поэтому pid, который система успела выдать
кому-то другому, никогда не будет назван. Если заметки нет или процесс мёртв,
клиент возвращается к прежнему общему предупреждению — придумывать pid он не
станет.

Почему заметка, а не `lsof` или `/proc`: их нет в Termux и они разные на каждой
платформе, а процесс, который мы ищем, всегда наш собственный.

Замок при этом висит на **разговоре**, а не на порту — от этого зависит всё
дальнейшее. Нужен он потому, что второй клиент, который слушать не может, но
звонить продолжает, заставляет канал у собеседника метаться между двумя
процессами: с обеих сторон это выглядит как «связь всё время рвётся».

**Другой собеседник — расходимся мирно.** Делить нечего, поэтому второй чат
продолжает звонить, просто без слушателя:

```
* port 4747 belongs to your other conversation — this one dials out only
* that is a full chat: one connection carries both directions
```

Это полноценная переписка: одно TCP-соединение несёт оба направления — тот же
случай, что shared node с quarantine. Так с одной машины работают два разговора
одновременно; раньше второй молчал наглухо.

**Тот же собеседник — побеждает новый запуск.** Раз команда набрана заново,
прежний экземпляр того же разговора считается забытым, и клиент закрывает его
сам:

```
* a forgotten tailchat for this conversation holds the port — closing pid 31210
* listening on 100.122.98.16:4747
```

Уходит только `SIGTERM`, только тому pid, за который поручилась наша же заметка,
и только если процесс жив. `SIGKILL` не применяется никогда. Вытесненный
экземпляр успевает восстановить терминал и убрать свою заметку. Не отдал порт за
три секунды — клиент не эскалирует, а возвращается к поведению ниже.

**Разговор в заметке не назван** — держатель старше `0.42.14`, такие писали
только pid. Тогда всё как раньше: сообщение с pid, `● OFFLINE` и никаких
сигналов. Закрывать процесс, чей разговор нельзя назвать, клиент не станет.

Слушатель в любом случае не сдаётся: как только порт освобождается, клиент
занимает его и снова становится полноправным участником.

```
* the port is free again — this client is now the one listening
```

Перезапускать ничего не нужно.

## Картинки

`/asc <настроение>` отправляет картинку: `happy`, `sad`, `ok`, `no`, а также
`cat`, `dog`, `bird`, `shrug`, `coffee`, `cow`. Без аргумента — любая. У каждого
настроения несколько вариантов, чтобы не приедалось. Опечатка в названии не
угадывается, а показывает список: отправить не то чувство хуже, чем ничего.

Все картинки — чистый ASCII: один символ равен одной ячейке, поэтому рисунок не
разъезжается ни на узком терминале, ни у собеседника со шрифтом без нужных
глифов. Ширина и высота ограничены тестом, чтобы шутка не хоронила разговор.

## Третий собеседник — ИИ

`/ai <вопрос>` приглашает в разговор третьего. Он отвечает **в ту же переписку**,
которую читают оба: строка приходит от своего имени (по умолчанию `tailik`),
своим цветом, и её видит собеседник — иначе это не участник разговора, а частная
справка при свидетелях. Поэтому и сам вопрос уходит в общий канал: ответ без
вопроса на чужом экране выглядит как бормотание.

Обычная светская реплика сама по себе ИИ не вызывает: на `как дела?` люди
отвечают друг другу. Для прямого ответа нужно назвать `tailik`/«Тэйлик»,
использовать `/ai <вопрос>` или продолжить непосредственно его предыдущую
реплику без повторения имени.

Если ИИ не приглашали, после **15** таких человеческих реплик он делает один
короткий recap разговора. Строка с `*` в начале адресована только человеку,
не получает прямого ответа и не входит в счётчик recap:
`* roman, как дела?`.

Он знает tailchat изнутри: в его контексте живёт настоящий список команд с
описаниями и настройки приложения, так что «как отправить файл?», «где лежит
конфиг?» или «что делает /wake?» — вопросы к нему, как и всё остальное.
Команды терминала он выполняет сам, до трёх на вопрос: в ответе он пишет строку
с `!` (`!ls -la`), клиент выполняет и возвращает вывод, и только потом модель
отвечает. В переписке видно, что запущено: `tailik выполняет: …`. Команды
исполняются на машине того клиента, чей ИИ отвечает. Учти: ответ модели
ненадёжен, а сообщение от собеседника может протащить в контекст чужую
инструкцию, — поэтому разрушительную команду модель обязана сначала проговорить
вслух.

Команда с `!@хост` в начале (`!@kali df -h`) выполняется по SSH на другой
машине tailnet: используется твой `~/.ssh/config` — алиас, порт, ключ.
Разрушительное не выполняется вообще, как класс: `rm -rf` (любое написание
флагов), `mkfs` по устройству, запись в блочное устройство, `shutdown`/`reboot`
и форк-бомба отклоняются до запуска, и модель слышит почему. Остановить ИИ
посреди ответа — `/stop`: прерывает запрос и убивает выполняемую команду.
История версий (`docs/worklog.md`) — встроенный инструмент, без шелла и без
подтверждения: `!changelog` — последние записи, `!changelog 0.47.0` — одна
версия, `!changelog since 0.45.0` — всё от неё до верха. Спроси «что нового в
0.47.0?» — ответит по файлу.
Поиск в вебе — тоже встроенный инструмент: `!search <запрос>` возвращает
короткий список результатов (заголовок, адрес, сниппет) через DuckDuckGo —
Google скрейпинг блокирует. Браузер не нужен: «найди в гугле про X» работает.

Кроме терминала, ИИ умеет запускать и сами команды tailchat — но не любые, а
короткий безопасный список: `/theme`, `/clear`, `/logo`, `/holiday`, `/saver`,
`/mouse`, `/asc`, `/happy`, `/sad`, `/neutral`, `/help`, `/version`, `/files`,
`/history`.
Ничего, что отправляет файл, меняет собеседника, секреты или перезапускает
клиент, в этот список не входит. Строка с одной такой командой (`/theme ocean`)
уходит через тот же диспетчер, что и набранная вручную — значит, ничего сверх
того, что мог бы сделать человек тем же нажатием клавиш. «Смени тему на ocean» —
рабочая просьба.

Контекст он видит с обеих сторон и различает, кто есть кто: каждая реплика
приходит к модели со своим автором, поэтому на вопрос «кто из нас двоих это
сказал» он отвечает по существу. В памяти держатся последние 24 реплики —
не файл журнала, потому что журнал можно выключить (`/logs off`).

На адресованную реплику отвечает **ровно один** клиент. Способный AI на стороне
автора владеет вопросом; если там AI выключен или ключа нет, Mac-клиент с
рабочим AI даёт fallback. Неадресованные сообщения остаются человеческим
разговором до общего recap после 15 реплик.

Собеседник постарше — клиент до `v0.43.0` — кадра `ai` не знает и раньше просто
не видел ответов: на его экране оставался только вопрос. Теперь такому
собеседнику ответ уходит обычным сообщением, а имя автора несёт сам текст:
`tailik: ...`. Подпись внутри строки хуже настоящего автора и куда лучше
половины разговора; как только он обновится, ответ снова приходит своим кадром.

```
/ai <вопрос>        общий вопрос — отвечает единственный AI-владелец
/ai                 показать настройку: имя, провайдер, модель, состояние
/ai off             выключить ИИ на этой машине (пир может ответить)
/ai never           полностью выключить ИИ — вопрос даже не публикуется
/ai on              слушать своё имя и делать recap после 15 реплик
/ai name <имя>      переименовать: /ai name бот
/ai key <ключ>      сохранить ключ на диск — дальше он берётся сам
/ai provider <имя>  сменить провайдера: gemini, openrouter или deepseek
/ai model [имя|номер] список или смена модели: /ai model 2, /ai model gemini-3.7-flash, /ai model default
```

В режиме "один AI на Mac" (`/ai on` на Mac, `/ai off` у Roman) команда Roman
`/ai <вопрос>` превращается в видимое `tailik, <вопрос>` и выполняется
Mac-клиентом. Его выключенный Windows-AI не запускается, даже если в старом
`secrets.env` остался ключ.

`/ai never` — полное отключение, сильнее `off`: вопрос не публикуется вовсе и
не уходит ни локальному, ни чужому AI. Подходит, когда ИИ не должен появляться
в разговоре ни с какой стороны. Вернуть любой режим — `/ai on`.

### Ключ

Ключ не попадает в `config.json` никогда: этот файл правят руками и показывают
другим. Он живёт рядом, в `~/.tailchat/secrets.env` — по строке `ИМЯ=значение`,
права `0600`, — и читается при старте, поэтому `export` не нужен вовсе.
Достаточно один раз набрать `/ai key <ключ>` в самом чате: он запишется под
именем переменной выбранного провайдера. Переменная окружения, если она задана,
всё равно старше файла — это способ подменить ключ на один сеанс.

| провайдер | переменная | модель по умолчанию |
| --- | --- | --- |
| `gemini` | `GEMINI_API_KEY` | `gemini-3.5-flash-lite` |
| `openrouter` | `OPENROUTER_API_KEY` | `nvidia/nemotron-3-nano-30b-a3b:free` |
| `deepseek` | `DEEPSEEK_API_KEY` | `deepseek-v4-flash` |

Одного ключа достаточно: если провайдер не выбран руками, берётся тот, чей ключ
уже есть — в окружении или в `secrets.env`. Бесплатный ключ Google даёт AI
Studio, ключ OpenRouter — его настройки; обоим хватает бесплатного тарифа. Ключ
DeepSeek берётся в его же консоли и бесплатного тарифа не имеет — платит за себя
сам, зато не кончается на середине разговора. Запрос уходит один за раз и не чаще
раза в четыре секунды, чтобы бесплатный лимит не кончился на одном разговоре.
Кончился всё-таки — `/ai provider <имя>` переводит ИИ на любого другого, вместе с
его моделью и его переменной, не выходя из чата.

Провайдера, модель и имя помнит `~/.tailchat/config.json` — и только то, что
выбрано руками: модель из набора по умолчанию туда не вписывается, иначе
улучшенное значение никогда бы не дошло до того, кто раз набрал `/ai on`.

```json
{ "ai": { "enabled": true, "name": "tailik", "provider": "openrouter" } }
```

Свой endpoint (что угодно, говорящее на диалекте OpenAI `chat/completions`)
задаётся полем `url`, а ключ к нему — именем `TAILCHAT_AI_KEY`: переменной или
строкой в `secrets.env`.

### Когда ответа нет

Клиент не выдумывает ответ и не молчит. Без ключа `/ai` показывает, какое именно
имя ему нужно и что достаточно набрать `/ai key <ключ>`. Отказ провайдера
приводится его собственными словами —
«credits depleted» и «нет такой модели» это одинаковый 4xx, но разные действия.
Отдельно называется случай, когда модель израсходовала весь бюджет токенов на
размышление и не дошла до ответа: у моделей с рассуждением он общий с ответом,
поэтому запас взят с большим избытком, а видимый ответ всё равно обрезается по
длине окна.

Ответы модели — данные, а не указания: они попадают в переписку как чужой текст
и никаких команд клиенту не отдают.

## Короткие команды

У каждой команды есть однобуквенная форма: `/q` = `/quit`, `/h` = `/help`,
`/s` = `/send`, `/p` = `/paste`, `/f` = `/files`, `/o` = `/open`, `/w` = `/wake`,
`/m` = `/mouse`, `/c` = `/clear`, `/i` = `/history`, `/v` = `/version`,
`/u` = `/update`, `/a` = `/happy`, `/d` = `/sad`, `/n` = `/neutral`, `/t` = `/theme`,
`/k` = `/nick`.

У `/asc`, `/ai`, `/logo`, `/holiday` и `/saver` короткой формы нет: буквы `a`,
`s`, `c`, `h` и `l` уже заняты, а выдуманная буква запоминалась бы хуже целого
слова.

## Логотип

Логотип живёт **не в переписке**, а в собственной полосе над ней: между
заголовком и историей. Поэтому он не уезжает при прокрутке, не стареет вместе с
буфером и его не забирает `/clear` — очистка опустошает переписку, полоса
остаётся.

Рисунка два, и берётся тот, что влезает. По умолчанию крест выключен: от 47
столбцов видны блочные буквы `tailchat` и подпись про тайлнет, от 32 — компактный
логотип. С крестом полный вариант требует 52 столбца, компактный — 37: знак
помещается даже в прежнем 39-столбцовом минимуме Termux. Если окно уже 37, но
сам компактный логотип ещё помещается, остаётся он без креста — лучше сохранить
имя приложения, чем завернуть рисунок.

`/holiday` переключает крест сразу у обоих собеседников; `/holiday on` и
`/holiday off` задают состояние явно. Выбор сохраняется в обоих `config.json`.
Если канала нет или второй клиент старее 0.57.24, команда честно меняет только
свой экран и сообщает об этом. Ширину даёт blessed, а не
`process.stdout.columns`: под tmux они на старте расходятся, а решает та, которой
рисуется рамка. Окно можно тянуть — рисунок переберётся сам.

Появляется он не сразу целиком. При запуске по нему один раз проходит полоса
`▌` слева направо — как будто его рисуют, — а в конце кот один раз мигает.
Дальше он просто стоит: анимация при каждом сообщении быстро стала бы
раздражением.

Статичный логотип стоит на месте **с первого кадра**, а полоса идёт поверх него
и начинается **после** блокирующей части запуска: `tailscale status`, `whois`,
`git log` для списка изменений. Иначе кадры расходуются, пока цикл событий
занят, и первое, что видит терминал, — уже готовый логотип: анимации нет, хотя
код её «проиграл». А пустая полоса, ждущая таймера, — это то, как логотип один
раз пропал совсем.

`/logo` проигрывает её заново — **и у собеседника тоже**: логотип, который
видит один человек, это не приветствие, а хранитель экрана. Кадр `logo` не несёт
ничего, кроме самого факта: что рисовать, каждый клиент знает сам и рисует своей
шириной. Клиент до `0.44.0` этого кадра не знает, поэтому ему логотип уходит
обычным сообщением — та же картинка, только без движения. Движение на чужом
экране ограничено по частоте, как и `/wake`: раз в десять секунд.


### Заставка

Полоса показывает одно из двух, и решается это в одном месте:

| что видно | что это значит |
| --- | --- |
| логотип стоит | кто-то за клавиатурой, и собеседник на связи |
| кот спит с `z` | либо канала нет, либо никто ничего не набирает |

Сон — глаза закрыты и `z`, приходящая и уходящая, шаг 200 мс. Надпись не
двигается ни в одном кадре, и переписка не закрывается ни на строку: всё живёт в
тех же трёх рядах. Ходящий взад-вперёд кот тут был и убран: тишина должна
выглядеть тихо.

Отдельного таймера у заставки нет: она висит на том же сигнале присутствия,
который и так решает, показывать собеседнику `ACTIVE` или `IDLE` (30 секунд без
нажатий или ушедший фокус окна). Первое же нажатие — и логотип снова стоит.

А если отсутствие было долгим — `AWAY`, заданная `/saver after` пауза и больше
(по умолчанию 15 минут), — логотип не
просто возвращается, а **рисуется заново**: та же полоса `▌`, что при запуске.
Возврат из `IDLE` обходится без церемоний: тридцать секунд — это пауза в
середине фразы, и прогон на каждую такую паузу быстро надоел бы.

Полноэкранный слой — уже не эта полоса. Сверху `TAILCHAT`, собранный собственным
пиксельным алфавитом 5×5, внутри первой `A` открыты кошачьи глаза. Под словом —
ночная сцена «кот на заборе» Joan Stark (`jgs`): кот сидит спиной к нам под
убывающей луной, забор идёт во всю ширину. Сцена взята дословно с
[asciiart.website/art/7597](https://asciiart.website/art/7597) вместе с подписью
автора — рисунок её, и подпись она просила оставлять на месте. Внизу строка про
тайлнет.

Своего фона у заставки нет — тот же фон терминала, что и у переписки, так что
переход на неё не перекрашивает окно. Цветной только рисунок, и цвет тот же
зелёный, которым нарисована полоса над перепиской. Поверх медленно дышит
phosphor: оттенок зелёного ходит от тёмного к яркому и обратно.

Гаснет по-разному — в зависимости от того, откуда заставка взялась. Показанная
вручную, командой `/saver`, реагирует только на клавишу: мышь ей отдана быть не
может, потому что вне терминалов семейства VTE blessed не отличает клик от
простого движения курсора — оба приходят как `mousedown` — и отличить «посмотрели»
от «тронули мышь» было бы нечем. Появившаяся сама, на `AWAY`, гасится клавишей и
любым движением мыши разом: раз мышь шевельнулась, за компьютером уже кто-то
есть, и различать клик от движения незачем. Обычно мышь отдана терминалу, чтобы
работало выделение текста; на время показа автоматическая заставка берёт её себе
и возвращает ровно в том состоянии, в каком взяла, а вызванная вручную мышь вообще
не трогает. Ни клавиша, ни мышь не попадают в черновик.

Окно можно тянуть и во время заставки: кадр, который перестал влезать, blessed
завернул бы вдвое и рисунок бы рассыпался, поэтому кадр пере-выбирается под
новый размер, а если не влезает уже ничего — заставка отдаёт экран обратно.

При появлении по кадру один раз проходит тот же вертикальный scanline `▌`, что и
в полосе. Дальше движется только небо и глаза: восемь отметок (`*`, `.`, `'`)
мерцают, каждая на своём счёте, буквы моргают раз за петлю, а петля в 48 кадров
закрывается ровно на нетронутом рисунке. Луна, кот, забор и сами буквы не
двигаются ни в одном кадре — это проверяется тестом поклеточно.

Кадра, как и у полосы, два, и берётся тот, что влезает. От 47×29 — буквы над
сценой и подпись `p2p over your own tailnet`. Меньше — сцена без букв, и тогда
имя уходит в подпись: `tailchat - p2p over your own tailnet`; это 44×23, и
именно этот минимум проверяет `/saver`. Поднять один общий минимум до 29 строк
значило бы молча выключить заставку на узких терминалах, включая Termux, — а
заставка, которая отказывается показываться, хуже заставки без блочных букв.

Он же включается **сам** на `AWAY` — через заданную паузу без фокуса и клавиш
(по умолчанию 15 минут, настраивается `/saver after <минуты>`), честный
сигнал «человек ушёл» — и гаснет при первом возврате (клавиша, фокус окна или
движение мыши). Пауза общая с показанным собеседнику статусом `AWAY` в шапке —
отдельного таймера у заставки нет.
На `IDLE` (тридцать тихих секунд) он не трогает экран: это ещё может быть
читающий человек, а не ушедший. Termux фокуса не сообщает и до `AWAY` не
доходит, поэтому там экран не гаснет сам.

```
/saver              показать полноэкранную анимацию сейчас
/saver off          выключить автоматическую заставку (и сон в полосе)
/saver on           включить автоматическую заставку и показать её сразу
                    (настройка помнится в config.json)
/saver after 20     заставка (и статус AWAY у собеседника) — через 20 минут
/saver after        показать текущую паузу
```

## Если рамка поехала

`Ctrl+G` стирает весь черновик и перерисовывает окно целиком. Это же средство
против испорченного кадра после изменения размера окна или чужой
escape-последовательности. Одиночный `Esc` намеренно ничего не делает: он
неотличим от начала escape-последовательности, и терминал его придерживает.

## Индикатор набора

Пока кто-то печатает — включая тебя самого — надпись `<имя> typing` переливается
**на разделителе черновика**, а шапка продолжает показывать присутствие.
Одновременные голоса объединяются: `Alice + Roman typing`, с ИИ —
`Alice + Roman + tailik typing`.
Каждый `stop` убирает только своё имя; разрыв соединения очищает все удалённые
голоса. Индикатор гаснет после отправки или трёх секунд простоя. На канал
уходит не больше одного кадра в две секунды — быстрый набор не превращается в
поток служебных сообщений.

`/typing off` отключает **только собственное отображение** — «Alice typing»
на разделителе черновика у себя же. Собеседнику это ничего не меняет: он
по-прежнему видит, что вы печатаете, безусловно и всегда — кадр уходит тем же
путём, что и индикатор ИИ. Переключение посреди слова синхронизирует
отображение немедленно, а не ждёт следующего нажатия клавиши. Выбор помнится в
`config.json`. Текущее состояние — `/typing` без аргумента.

## Редактирование черновика

Стрелки `←`/`→` двигают курсор, `↑`/`↓` — между строками многострочного
черновика, `Home`/`End` (или `Ctrl+A`/`Ctrl+E`) — к началу и концу строки,
`Backspace` и `Delete` удаляют слева и справа от курсора, `Ctrl+U` очищает
строку, `Ctrl+W` — слово слева, `Ctrl+K` — до конца строки. Вставка идёт в позицию
курсора. Эмодзи считается одним символом — курсор не встаёт между половинами
surrogate-пары.

Это собственная реализация: в `blessed` обработка стрелок в textarea —
незаполненная заглушка, поэтому набранное можно было править только backspace.

## История переписки

С флагом `--log <file>` каждая строка переписки уходит на диск, поэтому история
переживает переподключения и перезапуск: при подключении показывается цветной
хвост из файла (до 20 сообщений), а `/history` вытягивает из него ещё, до 100
сообщений — см. «История» выше.
В лог попадают **обе стороны** — и входящие, и свои сообщения (свои — только
после фактической отправки). Служебные события (`connected`, `listening`,
`rejected inbound`) не пишутся.

Лог локальный: в файле только то, что видел твой клиент. Сообщения, отправленные
пиром при выключенном клиенте, не догоняются — в P2P без сервера их неоткуда
взять.

Файл создаётся с правами `0600`, а уже существующий ужимается до `0600` перед
дозаписью. Содержимое хранится открытым текстом: WireGuard шифрует канал, но не
файл на диске.

Emoji отображаются корректно: `src/wide-chars.js` чинит таблицы ширины
`blessed@0.1.81`, который не знает современные эмодзи-блоки и считал `🚀`
шириной в одну ячейку, из-за чего разметка разъезжалась. Символы с variation
selector (`❤️`) выводятся в текстовом начертании — так ширина совпадает у
терминала и у `blessed`.

## TUI, вставка и уведомления

Полноэкранный TUI разделяет header, историю и поле ввода. На узких терминалах
(`50×16` и похожих) header и подсказка автоматически сокращаются. Цветной режим
включён по умолчанию; `--no-theme` и `NO_COLOR` сохраняют рамки, но используют
ASCII-статусы без цвета. Сама расцветка — не одна: `/theme` без аргумента
показывает текущую и список остальных (`green`, `amber`, `ocean`, `matrix`),
`/theme ocean` переключает сразу, без перезапуска, и запоминает выбор в
`config.json`. Меняются только цвет своих/чужих/ИИ-реплик и рамка окна —
остальное (код, ссылки, статус собеседника) значит одно и то же в любой теме,
так что цвет не путают со смыслом.

Терминалы с bracketed-paste могут вставить многострочный текст в composer:
переносы остаются в draft, автоматической отправки нет. Один Enter отправляет
весь draft одним сообщением с сохранёнными `\n`.

Native-уведомление со стандартным звуком появляется только для входящего
сообщения, когда окно терминала не в фокусе. На macOS может потребоваться
разрешение Notification Center; Windows использует Toast. Если native backend
не сработал, клиент подаёт terminal bell. `--no-notify` отключает оба механизма.

## Как это работает
Оба инстанса одновременно слушают порт и пытаются подключиться к пиру.
Побеждает один канал (дедуп по случайному `connId`); достаточно одного рабочего направления.
Inbound принимается только с IP, разрезолвленных из указанного `<peer-addr>`.
Для shared node владелец указывает адрес получателя, видимый из своего tailnet.
Если фактический source IP входящего соединения не совпал с разрешённым
`<peer-addr>`, TUI покажет `rejected inbound from ...` для точной диагностики.
Tailscale ACL и quarantine shared-node продолжают ограничивать сетевой доступ.
Трафик шифрует WireGuard самого tailnet — приложение своего крипто не добавляет.

Поверх этого канала ходят кадры, размеченные полем `t`: `hello`, `msg`, `ack`,
`read`, `typing`, `focus`, `wake`, `bye`, `devices`, `update`, `caps`, `file-*` и
`ai` — реплика третьего собеседника со своим автором, а не наше сообщение.
Незнакомый `t` каждая сторона молча пропускает, поэтому клиент постарше просто
не увидит ответа ИИ вместо того, чтобы приписать его нам.

## Экспериментальный шифр — не используется в Tailchat

[`experiments/tail-feistel.js`](../experiments/tail-feistel.js) содержит собственную
конструкцию **TailFeistel-256/experimental-v1**: блочную сеть Фейстеля с
раундовой функцией на стандартном HMAC-SHA-256. Это не обёртка над AES и не
новая реализация SHA-256.

**Только эксперимент. Криптоанализ и независимый аудит не проводились;
стойкость неизвестна. Для реальных секретов не использовать.** Число 256
обозначает размер блока, а не доказанный уровень безопасности.

* Ключ — 32 байта; блок — 32 байта, две половины `L` и `R` по 16 байт.
* Восемь раундов, `i = 0..7`; конкатенация ниже обозначена `||`.
* Метки кодируются ASCII, после каждой стоит один нулевой байт.
* `uint8(i)` — один байт; `first16` — первые 16 байт результата.

```text
K_i = HMAC-SHA-256(K, ASCII("TailFeistel-256/experimental-v1/key") || 0x00 || uint8(i))
F_i(X) = first16(HMAC-SHA-256(K_i, ASCII("TailFeistel-256/experimental-v1/round") || 0x00 || X))

Раунд шифрования:   (L, R) → (R, L XOR F_i(R))
Обратный раунд:     (L, R) → (R XOR F_i(L), L)
```

Шифрование выполняет раунды от 0 до 7, расшифрование — от 7 до 0;
результат — `L || R`, без дополнительного обмена половин.
`createTailFeistel(key)` возвращает `encryptBlock(block)`,
`decryptBlock(block)` и `destroy()`. Входы — `Buffer` или `Uint8Array`
ровно по 32 байта, результат — новый `Buffer`. Уничтоженный экземпляр
больше не шифрует и не расшифровывает; очистка буферов не гарантирует
удаления всех копий из памяти JavaScript/OpenSSL.

Это детерминированное преобразование одного блока: нет nonce, режима для
произвольных сообщений, padding, проверки целостности или обнаружения
неверного ключа. Нельзя шифровать длинный текст независимыми блоками:
получится ECB с утечкой повторов. Это не E2EE-протокол Tailchat.

Запуск демонстрации с **заведомо публичным тестовым ключом**:

```bash
node experiments/tail-feistel.js
node --test test/tail-feistel.test.js
```

Проверки подтверждают соответствие алгоритму и обратимость, не стойкость.
Web, Android, CLI, серверное хранилище и транспорт этот модуль не используют.
