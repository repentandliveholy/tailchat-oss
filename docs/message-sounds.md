# Web message cues (received/sent/wake) — звуки сообщений

Встроенные куи: v1.11 (после прослушивания пользователем в приложении),
задеплоены на OVH (tailchat-cloud 1.11).

Файлы: `web/cloud/sounds/{received,sent,wake}.mp3`, источник и лицензия —
`web/cloud/sounds/CREDITS.txt`. Играются из `web/cloud/app.js`:
`SOUND_FILES` (URL с `?v=APP_VERSION`), громкость через `SAMPLE_GAIN`,
синтезированные `SOUND_CUES` — только фолбэк, если сэмпл не загрузился.

  wake=magic marimba (2820). Коммит утверждал «chosen by ear», но прогон
  `afplay` был для пользователя неслышим (exit 0, volume 44 — вероятно,

  «ужасный», попросил «мягкий низкий приятный».
- v1.11: входящее заменено на Magic marimba (2820), первые 1.8 s фразы с
  фейдом (полная фраза — wake). Выбрано пользователем по audition-странице
  с 10 кандидатами (громкость выровнена loudnorm, длинные обрезаны до
  1.8 s). sent/wake не менялись.

Правило звука (введено в v1.11, `notifyReceivedSound` в app.js): received-звук
— это уведомление. Не играет, когда сообщение пришло в открытый и
сфокусированный диалог (пузырь сам по себе — сигнал), и схлопывает пачку до
одного попа на собеседника в 3 s. Это убрало «звук на каждое сообщение при
прочтении накопленного» («когда прочитываю много новых — не повторять на
каждый; вообще при прочтении звуки не нужны»).

| wake.mp3     | 2820 Magic Marimba (полная фраза) | 3.34 s | -19.7 / -1.6 | 81.5 KB |

Замечание: received и wake — одна и та же фраза маримбы (received = начало).
Если в будущем понадобится различать их на слух — см. пул кандидатов ниже
и процедуру замены.

Обработка: исходники (lossless wav/mp3) → `volume` до целевого пика →
mp3 192 kbps CBR, 44.1 kHz stereo, метаданные срезаны
(`-map 0:a:0 -map_metadata -1 -write_id3v1 0 -id3v2_version 0` — без этого
у части wav от Soundminer в mp3 уезжает встроенная картинка и файл
раздувается: received без среза был 224 KB вместо 10 KB).

`SAMPLE_GAIN` в app.js: `{ sent: 0.9, received: 0.6, wake: 0.9 }`.
`sent` поднят с 0.35 до 0.9: typewriter-клик — резкий пик при тихом RMS,
на 0.35 он был бы почти неслышен. Эффективный уровень микс сохраняет
характер: sent едва слышен, wake — через комнату.

## Пользовательский звук входящего сообщения

В настройках веб-клиента можно выбрать собственный звук входящего сообщения,
прослушать его сразу после выбора и вернуться к встроенному. Файл должен иметь
MIME-тип `audio/*`, весить не более 2 МБ и успешно декодироваться текущим
браузером; неподходящий файл не заменяет действующий звук.

Аудиоблоб хранится локально в IndexedDB: база `tailchat-cloud`, хранилище
`sounds`, ключ `received`, значение `{ blob, name, ts }`. Имя для быстрой
отрисовки строки настроек дублируется в `localStorage` под ключом
`tailchat-cloud-sound-file`. При замене и сбросе старый object URL отзывается,
а сброс также удаляет запись из IndexedDB.

Для пользовательского файла не применяется `SAMPLE_GAIN`: его неизвестная
исходная громкость регулируется только общим ползунком, с ограничением
итогового gain до 1. Настройка относится только к текущему браузеру/устройству:
клиентские настройки звука не передаются ни в одном серверном frame.

## Как прослушать и заменить

Прослушать текущие: `afplay web/cloud/sounds/{received,sent,wake}.mp3`.
Сначала убедиться в устройстве вывода/громкости — см. оговорку выше;
`afplay` exit 0 ≠ звук реально слышен. Лучше слушать в браузере на стенде:
поднять локальный cloud (см. worklog/memory: `TAILCHAT_CLOUD_DATA=/tmp/…`
`node bin/cloud-server.js`) и открыть `/tailchat/` — звуки играют на
получение/отправку/wake.

Замена куя:
1. `afplay ~/.tailchat/sounds-candidates/wav/<файл>` — выбрать на слух.
2. Собрать: `ffmpeg -y -v error -i <src> -map 0:a:0 -af "volume=<N>dB"`
   `-ar 44100 -ac 2 -c:a libmp3lame -b:a 192k -map_metadata -1`
   `-write_id3v1 0 -id3v2_version 0 web/cloud/sounds/<cue>.mp3`
   Целевой пик: received ≈ -8 dBFS, wake ≈ -1.5 dBFS, sent ≈ -1.5 dBFS
   (у sent подъём обязателен — см. SAMPLE_GAIN выше). Проверить:
   `ffmpeg -i out.mp3 -af volumedetect -f null -` и `ffprobe -v error`
   `-show_entries format=duration -of csv=p=0 out.mp3`.
3. Обновить `CREDITS.txt` (источник, id, лицензия).
4. Релиз для PWA-пользователей — ОБЯЗАТЕЛЬНО квартет кэша (AGENTS.md
   правило 7): бамп `package.json`, `?v=` в `web/cloud/index.html`
   (×2) и `web/cloud/sw.js` `SHELL_ASSETS` (×5), инкремент `CACHE_NAME`
   (`tailchat-cloud-vN`), литерал в `test/cloud-sw.test.js`. Иначе
   установленный PWA вечно играет старое.
5. `npm test` (полный), коммит, пуш, деплой
   (`ssh ovh 'cd /opt/tailchat && node bin/production-deploy.js'`),
   проверка: `curl -s localhost:7683/health` → `{"ok":true}` и
   `curl -sI https://repentandliveholy.org/tailchat/app.js?v=<версия>` → 200.

## Хронология (почему так вышло)

1. Синтез (Web Audio) — «звуки неудачные».
2. Синтез 2 (два осциллятора + фильтр) — «звуки все еще неудачные».
3. uisfx «soft» CC0 (romainsimon/uisfx) — «звуки ужасные, скачай
   качественные».
4. v1.10: Mixkit (текущее). Выбор сделан без подтверждённого
   прослушивания — переслушать и при необходимости заменить по шагам выше.
