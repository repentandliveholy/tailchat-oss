# Облачный шлюз Tailchat на OVH VPS

## Цель

Дать новому собеседнику два способа входа без установки Tailchat или Tailscale:

- мобильный браузер: `https://repentandliveholy.org/tailchat/`;
- обычный терминал: `ssh tailchat@203.0.113.10`.

OVH — дополнительная точка входа, а не обязательная часть Tailchat. Обычный Tailchat продолжает работать как автономное P2P-приложение внутри Tailscale без OVH.

## Архитектура шлюза

```text
[ браузер: HTML/CSS/JS ] ── HTTPS + WebSocket ──┐
                                                │
[ SSH: простой построчный клиент ] ── TCP ──────┤
                                                ▼
                                  [ служба Tailchat Gateway на OVH ]
                                                │
                                  выбор собеседника через /peer
                                                │
                             [ браузер или SSH другого пользователя ]
```

Шлюз связывает двух присутствующих пользователей. Он не проксирует терминальный интерфейс и не зависит от запущенного Tailchat на Mac.

## Веб-доступ

- Caddy принимает `https://repentandliveholy.org/tailchat/` и сохраняет префикс пути при проксировании.
- Node-служба слушает `127.0.0.1:7681`.
- WebSocket доступен только по `/tailchat/ws`.
- Интерфейс использует нативные элементы браузера: список пользователей, список сообщений, `textarea` и кнопку отправки.
- Верстка поддерживает ширину от 360 px, `100dvh`, safe-area и экранную клавиатуру.
- Сообщения добавляются через `textContent`; бинарные WebSocket-сообщения не принимаются.

## SSH-доступ

- Системный пользователь: `tailchat`.
- `ForceCommand`: `/opt/tailchat/bin/tailchat-entry.sh`.
- Команда входа: `ssh tailchat@203.0.113.10`.
- Пользователь не получает оболочку или произвольный запуск команд.
- ForceCommand запускает простой построчный Node-клиент без terminal UI.
- Клиент соединяется только с локальным мостом `127.0.0.1:7682`.

Команды SSH-клиента:

```text
/peer ИМЯ  выбрать свободного собеседника
/who       показать присутствующих
/leave     завершить разговор
/quit      выйти
```

## Протокол присутствия и pairing

1. Клиент отправляет `hello` с отображаемым именем.
2. Шлюз возвращает `welcome` и общий список `users`.
3. Клиент отправляет `peer` с именем или идентификатором свободного пользователя.
4. Оба клиента получают `paired`.
5. `message` доставляется обоим: отправителю с `own: true`, собеседнику с `own: false`.
6. При отключении одного участника второй получает `unpaired`, а список присутствующих обновляется.

Имена нормализуются и делаются уникальными. Длина имени ограничена 24 символами, сообщения — 4000 символами.

## Службы и порты

- `tailchat-gateway`: `bin/gateway-server.js` под PM2, сетевое ядро — `src/gateway-server.js`.
- HTTP/WebSocket: `127.0.0.1:7681`.
- Локальный SSH-мост: `127.0.0.1:7682`.
- Публичный TLS-вход открывает только Caddy.

## Критерии готовности

- На ширине 360–390 px отсутствует горизонтальная прокрутка.
- Два браузера могут выбрать друг друга и обменяться сообщениями.
- Браузер и SSH-клиент могут выбрать друг друга и обменяться сообщениями.
- Вход из Termux не зависит от возможностей terminal UI.
- Старый путь `/chat/` не обслуживается; основной путь — `/tailchat/`.
- Обычный P2P Tailchat работает независимо от состояния OVH.
