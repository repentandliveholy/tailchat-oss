# Web 1.130 — эмодзи, картинки, превью ссылок, плоский дизайн

Статус: спека согласована с владельцем 2026-10-27 (три блока вопросов), код не начат.
База: web 1.129 (`958b357`). Клиент: только `web/cloud/*` (+ `src/cloud/server.js`
только если понадобится маршрут для ассетов). APK — следующим раундом по этой же
спеке (§11, см. «Отклонение от §11»).

## 0. Решения владельца

| Тема | Решение |
|---|---|
| Где быстрая реакция | Только строка в меню; hover-бар отменён владельцем 2026-10-28 («по hover не надо эмодзи»), см. F |
| Быстрый набор | 6 эмодзи + «+», набор настраивается в Настройках |
| Полный пикер | Вкладки категорий + поиск + «Недавние» |
| Отрисовка эмодзи | **Apple PNG везде, как Telegram Web**. Юридический риск (© Apple, проект MIT) владелец принял сознательно |
| Book (paper + serif) | Неровная подложка — **кнопка эмодзи в composer** |
| Просмотр картинки | Полноэкранный lightbox: зум, пан, листание ←/→ |
| «Скачать оригинал» | Кнопка убирается; сохранение — маленькая иконка в углу lightbox |
| Вставка картинки | Всегда превью перед отправкой (paste, drop, скрепка): crop, поворот, подпись |
| Картинка в ленте | Без баббла, время и метка поверх картинки |
| Превью ссылки | Адаптивное: большая картинка сверху / миниатюра слева / только текст |
| Мало данных у превью | Карточку не показывать вовсе |
| Направление дизайна | Плоский тональный: без обводок, разделение тоном и отступами |
| Обводки | Один тумблер «Обводки», по умолчанию **выкл** |
| Бабблы | Свои — тон акцента, чужие — нейтральная заливка |
| Галочки в ростере | Всегда в одном месте: вверху справа, слева от времени (как Telegram) |
| Клиенты | Web сейчас; APK следующим раундом по этой спеке |

Решено по умолчанию (владелец не спрашивался, консервативный выбор — можно
пересмотреть):
- Настройки быстрого набора и обводок — локальные для устройства (`localStorage`),
  как тема и обои; на сервер не синхронизируются.
- Несколько картинок за раз (drop/скрепка) — превью по очереди, по одной;
  у каждой свой crop.
- Поле ввода (`textarea`) продолжает рисовать системные эмодзи (см. A4).

## A. Эмодзи

### A1. Быстрые реакции
- **Hover-бар — удалён.** Владелец 2026-10-28: «по hover не надо эмодзи».
  Прежний абзац про показ через 150 мс и скрытие через 200 мс отменён;
  плавающей полоски, её таймеров и обработчиков наведения больше нет (см. F).
- **Строка в меню.** Остаётся первой строкой `openMessageMenu`, те же 6 + «+».
  Пункт меню «Реакция» (`msgReact` → `openReactionPicker`) **удаляется**: «+»
  в строке делает то же самое. Порядок остальных пунктов не меняется (§10:
  текстовые пункты остаются текстовыми).
- `QUICK_EMOJI` (10 штук, `app.js:5113`) и захардкоженная пятёрка
  (`app.js:9350`) заменяются **одним** источником — `quickReactions()` из
  настроек.
- Набор по умолчанию: `👍 👎 👌 ❤️ 🙏 🔥` (текущие пять из меню + 🔥).
- Настройки → «Поведение» → «Быстрые реакции»: 6 слотов; тап по слоту открывает
  полный пикер и заменяет эмодзи в слоте. Хранится в `tailchat-cloud-quick-reactions`
  (JSON-массив из 6 строк; невалидное значение — набор по умолчанию).

### A2. Отрисовка Apple-эмодзи
- Источник: `emoji-datasource-apple` (iamcal/emoji-data), PNG 64px по одному на
  глиф. Отдаются со своего origin (`/tailchat/emoji/apple/64/<codepoints>.png`).
  CSP уже пропускает: `img-src 'self'`.
- Состав: все fully-qualified эмодзи без вариантов тона кожи. Тон кожи — вне
  объёма этой спеки.
- Перед реализацией измерить общий размер. Бюджет — ≤ 10 MB в репозитории
  `[INFERENCE: оценка по 3–6 KB на PNG × ~1 900 глифов]`. Если не влезает — спрайт
  32/64px вместо отдельных файлов. Каталог эмодзи в `SHELL_ASSETS` **не** входит:
  кэшируется в runtime-кэш SW при первом показе, иначе установка PWA тянет мегабайты.
- Где рисуется PNG: текст бабблов (`renderMessageBody`), реакции под сообщением,
  строка в меню, пикер, превью в ростере, цитата ответа. Это
  `<img class="emoji" alt="<глиф>" draggable="false">` высотой `1.2em`,
  `vertical-align: -0.2em`. `alt` обязателен: копирование и выделение текста
  отдают исходный глиф, поиск по истории продолжает искать по тексту.
- Сообщение только из 1–3 эмодзи — «джамбо» 2.5em, без баббла (как картинка, B3).
- Протокол не меняется: в кадре по-прежнему Unicode. Терминал и APK получают
  то же, что раньше.
- Глифа нет в наборе — рисуется системный, как сейчас.

### A3. Полный пикер
- Один компонент на composer и на «+» у реакций. Размер ≤ 360×380, на телефоне —
  нижний лист на всю ширину.
- Сверху поле поиска (фокус сразу при открытии с мыши; на тач-устройстве — нет,
  чтобы не выпрыгивала клавиатура). Под ним полоса вкладок-иконок: Недавние,
  Смайлы, Люди/жесты, Животные/природа, Еда, Активности, Путешествия, Предметы,
  Символы, Флаги. Вкладка скроллит ленту к своему заголовку; при скролле
  подсвечивается активная вкладка.
- Поиск по ключевым словам ru + en: CLDR annotations (лицензия Unicode)
  + `short_names` из emoji-data. Пустой результат — строка «Ничего не найдено».
- «Недавние»: последние 24 выбранных, в composer и в реакциях общие,
  `tailchat-cloud-emoji-recent`.
- Клавиатура: стрелки двигают выбор, Enter выбирает, Esc закрывает
  (фокус возвращается туда, откуда пикер открыли).
- Сетка рисуется лениво (IntersectionObserver по категориям), чтобы открытие не
  создавало ~1 900 `<img>` разом.
- `EMOJI_GROUPS` (144 глифа) удаляется, вместо него таблица из emoji-data.

### A4. Composer и кнопка эмодзи (book)
- В `textarea` картинку не вставить, поэтому поле ввода рисует системный глиф. На
  Mac и iPhone это и так Apple; на Windows и Linux в поле виден системный, в ленте
  — Apple. Переход на `contenteditable` (как в Telegram Web) — вне объёма: он
  ломает `syncComposerMirror`, черновики и IME.
- Кнопка эмодзи в composer рисует Apple PNG (😊) как `<img>` в квадрате кнопки.
  Центрирование становится геометрическим и перестаёт зависеть от метрик шрифта
  `serif`/`mono` — это и лечит неровную подложку в book.
- Приёмка: в 6 темах × 2 режима × 3 шрифта центр картинки совпадает с центром
  кнопки ±0.5 px (`getBoundingClientRect`, скриншоты paper + serif до и после).

## B. Картинки

### B1. Lightbox (вместо `#attachment-dialog`)
- Полный экран, фон `#000` с прозрачностью 92%, без заголовка, без рамки, без
  `modal-card`.
- Открывается в режиме fit (вся картинка видна, без апскейла выше 1:1).
- Зум 1×–8×: колесо (точка зума — курсор), pinch (Pointer Events, два указателя),
  двойной клик или тап переключает fit ↔ 1:1 (если 1:1 ≤ fit — fit ↔ 2×).
- Пан при зуме > fit: drag мышью или пальцем, с ограничением краями картинки.
- ←/→ (и свайп по горизонтали при fit) — соседние картинки **текущей беседы** в
  порядке ленты; по краям — без зацикливания. Счётчик `3 / 12` вверху по центру,
  появляется вместе с контролами.
- Закрыть: Esc, клик по фону вне картинки при fit, свайп вниз при fit, кнопка ✕.
- Контролы (✕ и иконка сохранения) — в правом верхнем углу, полупрозрачные;
  скрываются через 2 с бездействия и появляются при движении мыши или тапе.
- Сохранение: `<a download>` на текущий `dataUrl`/`blob` с именем
  `safeAttachmentName`. `downloadOriginal` из i18n удаляется (во всех 3 языках),
  вместо неё — `aria-label` иконки `imageSave`.
- `prefers-reduced-motion`: без анимации зума и перелистывания.

### B2. Превью перед отправкой (paste, drop, скрепка)
- `handlePastedImage` больше не отправляет сразу: он открывает лист превью. Все три
  входа (`paste`, `drop` → `queueBrowserFiles`, `#file-input`) для `image/*` идут
  через лист. Не-картинки — как сейчас.
- Лист: картинка на всю доступную площадь; внизу — панель «Обрезать», «Повернуть
  90°», поле подписи, кнопка «Отправить».
- Crop: рамка с 8 ручками поверх картинки, затемнение снаружи. Пресеты: Свободно,
  1:1, 4:3, 16:9 (у 4:3/16:9 ориентация следует за картинкой). «Сбросить»
  возвращает исходник.
- Enter отправляет (если фокус не в многострочной подписи с Shift), Esc отменяет,
  ничего не отправляя.
- Результат: crop и поворот на `canvas` → существующий `compressImage` (те же
  лимиты, тот же `imageTooBig`).
- Подпись: непустая уходит в `text` кадра. Пустая — `t('pastedImage')`, как сейчас,
  потому что APK и терминал показывают `text` (§13: проводной формат не меняется).
- Отмена вставки ничего не пишет в беседу и не трогает черновик.

### B3. Картинка в ленте
- Сообщение, где есть `image` и нет подписи, рисуется без баббла: без заливки,
  обводки и автора `{name}`; картинка со скруглением `--radius-m`.
- «Нет подписи» — это `text` пустой или совпадает с плейсхолдером на любом языке
  (`🖼 [Изображение]`, `🖼 [Image]` и т. д. — множество из всех `pastedImage`).
  Сейчас этот плейсхолдер печатается над картинкой — убрать.
- Время и метка — плашка в правом нижнем углу картинки:
  `rgba(0,0,0,.45)`, белый текст, скругление 999px. Лестница меток §12 не меняется:
  ✓/✓✓ белые, «прочитано» — `--signal` поверх тёмной плашки (проверить контраст ≥ 3:1).
- С подписью — картинка сверху, подпись под ней в обычном баббле той же ширины,
  что картинка; время в баббле подписи.
- Реакции такой картинки — под ней, без подложки баббла.
- Меню цепляется к картинке так же, как к бабблу; hover-бар отменён (F).
- Убрать `.msg-image:hover { transform: scale(1.02); filter: brightness(1.1) }`:
  с lightbox это лишнее движение.

## C. Превью ссылок

- Карточка показывается только при наличии `title`. Нет `title` — карточки нет
  (голая ссылка в тексте). Картинка без `title` карточку не создаёт.
- Раскладка выбирается после загрузки картинки по её натуральному размеру:
  - **hero**: `naturalWidth ≥ 240` и `w/h ≤ 2.2` — картинка на всю ширину карточки,
    сверху, `max-height: 280px`, `object-fit: cover` только если обрезка ≤ 15%,
    иначе — исходная пропорция.
  - **thumb**: картинка есть, но меньше — 56×56, `object-fit: cover`, слева; текст
    справа.
  - **text**: картинки нет или она не загрузилась — только текст. Ошибка загрузки
    переключает уже отрисованную карточку на `text`, не оставляя пустого места.
- До загрузки картинки карточка не вставляется (ни скелетона, ни прыжка).
  `followTailGrowth` вызывается один раз, после вставки.
- Текст: сайт (1 строка, muted), заголовок (2 строки), описание (2 строки, только в
  hero и text). Пустые поля не создают элементов.
- Ширина карточки = ширина баббла. **Текстовый** баббл со ссылкой получает
  `min-width: min(320px, 100%)`, чтобы короткий текст не сжимал карточку в
  столбик. Исключение — картинка с подписью-ссылкой: ширина подписи и карточки
  равна ширине картинки (§B3), `min-width: 0`, без пустой подложки сбоку.
  Внутренние отступы одни — `--step-2` — у всех трёх раскладок.
- Подложка карточки — тон на шаг темнее или светлее баббла, без обводки (при
  «Обводки: вкл» — `--edge`). Hover без `translateY` и тени.
- YouTube: hero с плашкой ▶, как сейчас.
- Сервер (`/api/link-preview`) не меняется.

## D. Плоский дизайн и тумблер «Обводки»

### D1. Токены
- Новые токены в `:root`: `--edge` и `--edge-soft`. При `data-borders="on"` они
  равны `--line` и `--line-soft`, при `off` — `transparent`.
- Все декоративные `border*-color` в `app.css` переводятся на `--edge`/`--edge-soft`;
  ширина рамки остаётся, поэтому переключение не сдвигает раскладку.
- Не трогаются: `:focus-visible` (доступность), разделители внутри таблиц и списков
  настроек, а также рамка, которая несёт смысл (`bubble--pending`; при `off` её
  заменяет `opacity: .7`).
- Тени: только у плавающих слоёв — меню, пикер, диалоги, lightbox-контролы, hover-бар.
  У бабблов, карточек и строк ростера `box-shadow` убирается. Это откатывает
  «depth» из 1.128 для неплавающих элементов.

### D2. Поверхности
- Свои бабблы: `color-mix(in srgb, var(--signal) 14%, var(--surface))` (точный
  процент подбирается по теме так, чтобы контраст текста был ≥ 4.5:1).
- Чужие: `--raised`. Поле ввода: тональная заливка `--raised` вместо рамки.
- Ростер: активная строка — тон, а не рамка; hover — `--signal-soft`.

### D3. Настройка
- В «Оформлении» сегмент «Рамки сообщений» (`#bubbles-group`,
  `data-bubbles=plain|outlined`, `BUBBLES_KEY`) **заменяется** тумблером
  «Обводки»: `data-borders=off|on`, ключ `tailchat-cloud-borders`, по умолчанию `off`.
- Миграция при загрузке: `BUBBLES_KEY=outlined` → `on`, `plain` → `off`; старый
  ключ удаляется. CSS-правила `:root[data-bubbles=…]` (`app.css:4561–4587`) удаляются.
- i18n: `settingsBorders` (ru/en/fr); строки `bubbles*` удаляются.

### D4. Подобранные тона (реализация)

`--own-tone`: 14% по умолчанию, 20% для paper/light, 12% для mono/light.
Формула — D2, без градиентов поверх неё: обои не просвечивают через заливку
сообщения. Цвет авторов своих сообщений и цитат — `--own-accent`
(`color-mix(in srgb, var(--signal) 70%, var(--ink))`): чистый акцент на своей
подложке в светлых green/amber/matrix не держит 4.5:1. Цвет метаданных в paper —
`--ink` с обеих сторон; в mono/dark у своих сообщений —
`color-mix(in srgb, var(--muted) 50%, var(--ink))`; в остальных — `--muted`.
`read` по-прежнему получает неизменённый `--signal` (§12).

## E. Галочки в ростере — всегда в одном месте

- Сейчас `.roster-mark` стоит внутри строки превью сразу за текстом
  (`buildRosterPreview`, `.roster-preview-text { flex: 0 1 auto }`). Поэтому её
  положение по горизонтали зависит от длины сообщения: на коротком — в середине
  строки, на длинном — у края.
- Решение владельца (2026-10-27): как в Telegram, вверху справа, **слева от
  времени** — `✓✓ 12:40`. Время и метка — один flex-контейнер в колонке `badge`,
  `align-self: start`, метка первой, зазор 4px. Если у строки нет времени, метка
  стоит на том же месте.
- Строка превью освобождается от метки и получает всю ширину. Состояния §12
  (⧗/✓/✓✓/✓✓ цвета прочтения/⚠), `--receipt-size`, `setMark` и логика
  «неоседлых» ⧗/⚠ не меняются.
- Проверка: короткое и длинное превью, строка с бейджем непрочитанных, строки
  AI, узкий ростер (ресайз), триггер `⋯` в правом нижнем углу.
- §11: APK (`rosterPreviewLine` в `CloudScreen.kt`) — следующим раундом вместе с
  остальным. В терминале превью последнего сообщения с меткой в ростере нет —
  менять нечего.

## F. Компактность (2026-10-28)

Приоритет владельца — компактность ленты. Изменения только в web; формат кадров,
APK, терминал, цвета/контраст и лестница меток §12 остаются прежними.

1. **Время в последней строке.** Время, значки изменения/напоминания, метка
   доставки и `⋯` находятся в правом нижнем углу содержимого. В конце текста
   стоит невидимая, недоступная для фокуса копия метаданных: она занимает ровно
   их ширину и переносится целиком только при нехватке места в последней
   строке. Ширина не оценивается по шрифту и не измеряется наблюдателями:
   копия обновляется существующими сеттерами меток и при изменении содержимого.
   Длинные URL переносятся, переносы строк и jumbo-эмодзи сохраняются.
   Под карточкой ссылки, файла, голосового или кнопками — только высота
   метаданных, без прежней отдельной строки с верхним отступом. Цитаты ответа
   и подпись пересылки остаются над содержимым. У подписи картинки время ведёт
   себя как у текста, у картинки без подписи остаётся угловая плашка.
   Реакции всегда отдельной строкой под содержимым, вне метаданных.
   Вертикальный padding обычного баббла уменьшен с 10 до 7 px; размер кнопки
   меню и дополнительная область попадания для пальца не уменьшены.
2. **Автор только там, где нужен.** У своих сообщений имени нет. У обычного
   сообщения собеседника в личном чате повтор имени собеседника также убран;
   соответствующий `.bubble-author` не создаётся. Автор AI (`kind === 'ai'`),
   служебного/официального аккаунта (`tailik`, `{tailchat}` и другие аккаунты,
   распознаваемые существующим `isServiceAccount`) или отличающийся от
   собеседника автор остаётся видимым. Подпись пересылки не меняется.
   Имя хранится в данных строки, поэтому экспорт и пересылка не зависят
   от наличия видимого элемента автора. Поиск, копирование, экспорт и пересылка
   игнорируют невидимую копию метаданных.
3. **Картинки крупнее.** Длинная сторона превью ограничена 480 px вместо
   320 px, ширина — доступной шириной ленты за вычетом её боковых отступов.
   Пропорции сохраняются, оригинал никогда не увеличивается; после загрузки
   реальные размеры изображения уточняют размеры из кадра. Подпись и плашка
   следуют ширине рамки изображения. Для сверхузкого оригинала сохраняется
   минимальная читаемая ширина рамки подписи, но само изображение не
   растягивается. Lightbox не меняется.
4. **Без эмодзи по наведению.** Hover-бар из A1 удалён полностью, включая
   таймеры, обработчики и CSS. Быстрые шесть реакций в меню, «+» полного пикера
   и слоты в настройках сохранены без изменений поведения.
5. **Форма картинок и тонкая подпись.** Картинка без подписи имеет форму
   пузыря: скругление `--radius-bubble` и малый угол `--radius-tail` со стороны
   отправителя. Полоса подписи под картинкой — отступ сверху 4 px, снизу 4 px,
   межстрочный 1.35 (одна строка ≈ 28 px вместо 38 px).

Проверить в браузере свои и чужие сообщения: короткий и многострочный текст,
заполненную последнюю строку, длинный URL, jumbo-эмодзи, ответ, пересылку,
изменение, tombstone, ссылку с карточкой, картинки с подписью/без неё,
голосовое, файл, кнопки и реакции. Повторить на узкой/широкой ленте во всех
трёх шрифтах, включая смену меток ⧗ → ✓ → ✓✓ → прочитано/⚠ и напоминания.

## G. Объёмный дизайн как опция; кольцо аватара по «Обводкам» (2026-10-28)

Запрос владельца: «прошлый объёмный дизайн верни как опцию в настройки.
обводку аватарок убери эту. аутлайн её вкл и выкл». Только web. С 1.133
объёмный вид — умолчание (владелец: «depth поставь по-умолчанию»).

1. **Настройка.** «Оформление» → рядом с «Обводки» переключатель «Объёмный
   дизайн» (en «Depth», fr «Relief»). Ключ `tailchat-cloud-depth`, значения
   `on`/`off`, по умолчанию **`on`** (с 1.133; в 1.132 — `off`); применяется при
   запуске как `document.documentElement.dataset.depth`, как `data-borders`
   (`getInitialDepth`/`setDepth`), а `index.html` уже несёт `data-depth="on"`,
   чтобы не мигал плоский вид до скрипта. Плоским остаётся только сохранённое
   `off` (его пишет лишь клик, поэтому выключившие в 1.132 свой выбор сохраняют);
   чтение не пишет в хранилище; ошибка `localStorage` даёт объёмный вид и не
   теряет выбор на сессию. Миграций нет.
2. **Что возвращается.** Токены 1.128 `--elev-edge/-1/-2/-3`, `--elev-inset`,
   `--sheen`, `--accent-glow`, `--glass-line`, `--shadow-up`, `--shadow-side`,
   `--own-bubble-border` (светлая и тёмная половины) и правила, которые их
   использовали, — целиком под `html[data-depth="on"]`, последним слоем
   `app.css`: тени и ободок у бабблов, ростер (шапка-карточка `.roster-self`,
   hover со сдвигом на 1px, активная строка с акцентной планкой, бейдж со
   свечением), аватары и аватар рейла, шапка и composer (`--elev-2`), карточки
   над composer, поле ввода и поиск вдавлены (`--elev-inset`), круглые кнопки,
   кнопка отправки и «вниз», плавающие слои (`--elev-3`), превью обоев, карточки
   инфо-панели и диалогов, логотип, плашка пустого состояния, тени панелей
   (`--shadow-up`/`--shadow-side`), «день»/«печатает».
3. **Как depth сочетается с «Обводки».** Depth не включает линии.
   `--glass-line` и `--own-bubble-border` выводятся из `--edge`/`--own-bubble-bg`
   и при «Обводки: выкл» прозрачны; цветная обводка своего баббла (1.128)
   появляется только при обоих тумблерах и уступает `bubble--pending` (пунктир
   `--line`), картинке без баббла и jumbo. Тень, ободок света и блик — не
   обводки, они остаются при «Обводки: выкл».
4. **Совместимость с компактной лентой (F) и картинками (B3).** Depth не
   меняет геометрию: `.bubble-content`, абсолютный `.bubble-meta` и
   `.bubble-meta-spacer`, jumbo, карточки ссылок, подпись картинки и цифры
   ростера остаются как в F/E. У картинки без подписи и у jumbo-строки нет ни
   блика, ни тени вокруг строки; тень (`--elev-1`) получает сама картинка
   (`.msg-image-wrap`), плашка времени не трогается. Состояния (выделение, поиск,
   pending, disabled, pressed) не перекрываются: исключены по имени или
   выигрывают по специфичности. Карточки внутри баббла берут только
   ободок света `--elev-edge`.
5. **Контраст.** Заливки с текстом не меняются: свой баббл остаётся
   `--own-bubble-bg`, открытая строка ростера — её тон из D, бейдж, кнопка
   отправки, логотип и метка — плоские заливки. Градиенты 1.128 с тоном акцента
   поверх баббла и активной строки не возвращены (на paper/dark они опускали
   автора цитаты ниже 4.5:1). Блик на баббле — плёнка белого 2% в тёмной
   половине (худший случай: автор цитаты в своём баббле, paper/dark,
   4.91 → 4.69 у самой верхней кромки) и 45% в светлой, где осветление только
   повышает контраст тёмного текста. Градиент бейджа и кнопки отправки в тёмной
   половине светлеет к верху, в светлой темнеет к низу (белый текст на нём;
   светлеющий градиент опускал бы green/light до 4.07:1).
6. **Кольцо аватара.** Кольцо у `.roster-avatar` (ростер, панель информации,
   «Сохранённые») убирается: рамка остаётся 1.5px, но `transparent`, поэтому
   размер и раскладка не меняются. При «Обводки: вкл» она снова цвета
   присутствия (`--av-ring`), вместе с ней — зелёный ореол онлайна (он часть
   кольца). Присутствие при «Обводки: выкл» читается заливкой (`--av-fill`) и
   цветом буквы. Аватар рейла (`.rail-avatar`) кольца не имел. Это снимает
   исключение «присутствие аватара» из D.

Проверить в браузере (6 тем × светлая/тёмная × «Обводки» выкл/вкл × depth
выкл/вкл): свой/чужой баббл, баббл с ответом (цитата), картинка без подписи
(нет рамки и блика, тень у самой картинки) и с подписью, jumbo, карточка
ссылки, голосовое, файл, выделение, найденное сообщение, pending, ростер
(hover, активная, бейдж, метка ✓✓ и время), аватары всех присутствий, шапка и
composer, меню/палитра/диалоги, кнопка отправки; переключение depth и
«Обводки» без сдвига раскладки; перезагрузка сохраняет оба выбора.
